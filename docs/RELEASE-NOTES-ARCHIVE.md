# 爱记谱 iJipu 0.13.0

> 插件**自身功能**更新（**不涉及引擎**：`vendor/engine` 与应用 0.15.0 引擎保持一致，本轮未动）⇒ 0.12.0 → **0.13.0**（MINOR）。

## 新增

- **工具条「应用打开」按钮（仅桌面端）**——看谱时一键交给**系统默认应用**去编辑。
  - **位置**：紧跟在「显示模式（视图）」组之后（试听 → 排版 → 设置 → 显示模式 → **应用打开** → 嵌入标题链接）。
  - **悬浮提示**：「使用默认应用打开」；点击等价于在资源管理器里**双击该 `.jps`**（走系统文件关联，
    在 Windows 上就是打开 iJipu 桌面版）。
  - **出现条件**：**桌面端**（`Platform.isDesktopApp` + 库为本地文件系统）**且**当前面板知道自己的文件——
    `.jps` 文件视图与 `![[x.jps]]` 嵌入**有**该按钮；**代码块**（```jps）没有"自己的文件"，不出现；
    **手机端不出现**（移动端既没有 electron 也没有"默认应用"这回事）。
  - **两个细节**：① `TFile.path` 是**库内相对路径**，实现里用 `FileSystemAdapter.getFullPath()` 换成绝对路径
    （不是本地文件系统就明确拒绝，不会静默失败）；② 点它之前会先把**未落盘的编辑刷下去**
    （`.jps` 文件视图走 `saveNow()`），否则外部应用打开的是旧内容；刷盘失败会明确提示、不假装成功。
  - 实现为一个独立小模块 `src/openExternal.ts`（`electron.shell.openPath`），失败一律 `Notice` 说出来
    ——这类交互最容易被误当成"点了没反应"。

## 验证

- `tsc -noEmit -skipLibCheck`：退出码 0
- `npm run smoke`：**160 passed, 0 failed**（原 155 + 本轮新增 5 条断言：按钮位置/文案与悬浮提示、
  仅桌面端且仅知道文件时渲染、走 `shell.openPath` 且做绝对路径换算并失败 `Notice`、
  两个自带文件的入口都传 `filePath`、打开前先刷未落盘编辑）
- `npm run build`：产物 `main.js` 已含新按钮；`electron` 保持 external（`require("electron")`）

## 升级

打开任意 `.jps` 文件（或在笔记里写 `![[某个.jps]]`）即可看到「应用打开」；纯 `.jps` 代码块里不会出现。
桌面端才有该按钮；手机端界面不变。

## 变更

- 无破坏性变更：本轮只新增按钮与一个模块，工具条其余按钮的位置、行为、样式均未变。

# 爱记谱 iJipu 0.10.1

> 本版只做一件事：**同步 `@ijipu/engine`（0.13.1 → 0.13.2）**，带来两处谱面渲染 / 格式化修复。

## 同步的引擎修复

- **跨行连音线端点弧线不统一**（`adj459`）：音符比较靠近左边距时，结束弧线会明显比别处小。
  半径改为**同时受「层级间距」与「两端水平距离」约束**（单音符取 `|Δx| - 1`、多音符取 `|Δx| / 2 - 1`），

- **`+` / `-` 变号未断开**（`adj460`）：`5"注释"++++---` 现在格式化为 `5"注释"++++ ---`
  （同向追加不断开、**变号处断开**）；连音线前缀 `(y…` 内部不插空格。

## 说明

- 语法与语义**零变化**，`docs/SYNTAX.md` 无需改动；排版不位移（只是弧线 / 空格的呈现修正）。
- 应用侧同版本（iJipu `0.24.0`）另含「底部 dock：告警 / 试听 / 导出 / 设置四面板合一」，
  属应用 UI，与本插件无关。

# 爱记谱 iJipu 0.10.0

> 本版有两件事：**工具条图标换用与应用同源的成套图形**（不再"照着应用手绘"），
> 以及随 `@ijipu/engine`（0.13.0 → **0.13.1**）同步的**谱面修饰符换矢量图**。
> 插件侧**不需要改笔记里的任何写法**——语法与语义零变化，只是"画出来的样子"变了。

## 改进：工具条图标与 iJipu 应用完全同源

- **试听 / 排版 / 设置 / 谱面 / 满宽 / 整页**六个按钮改用应用 `public/icons/` 里的**同一批 PNG**
  （取「试听→播放、排版→排版、设置→设置、谱面→谱面、满宽→页宽、整页→整页」；试听中切换的「停止」
  也一并换成同套图，避免一个按钮两种笔画粗细）。
- **不再"照着应用手绘一套"**：此前 `src/icons.ts` 手绘内联 SVG 来对齐应用，两边各画一份必然漂移
  （本插件历史上就为对齐应用把「页面设置」从滑杆改成齿轮、线宽 1.4 提到 1.8）。现在直接用同一份图，
  且与应用**逐字节一致**（同步进 `vendor/icons/`）。
- **颜色随主题自动跟随**：只取 PNG 的 **alpha 通道**当形状，颜色交给 CSS
  （`background-color: currentColor` + `mask`）——亮/暗主题、悬停、以及「排版」按钮的
  选中态（强调色底）**全部自动同色**，不需要为深色主题另备一套图，也不会"黑线稿铺在深色底上隐形"。

## 引擎同步：谱面里的波音 / 滑音 / 延长记号改为矢量图

- 七枚符号（`&sby`/`&xby`/`&sby+`/`&xby+` 波音、`&shy`/`&xhy` 滑音、`&yc` 延长记号）从引擎此前手绘的
  矢量近似，改为**内联用户提供的 SVG 路径**——既是设计者给的原始图形，又保住**无损矢量**
  （导出/打印放大不糊）。
- 尺寸沿用既有占位口径（波音 9s/13.5s、延长记号 9.6s、滑音按高度贴合），**排版不会位移**；
  `docs/SYNTAX.md` 的语法说明**无需改动**（语义没变，只是图形换了）。

## 自包含性未变（发布物仍是三个文件）

- 图标在**构建期内联成 base64 data URI** 编进 `main.js`：发布物依旧只有
  `main.js` / `manifest.json` / `styles.css`，**不带任何图标目录**（社区发布与 `copy2ob.bat` 都只拷这三个）。
- `esbuild.config.mjs` 增加 `png-dataurl` 插件、`vite.config.ts` 设 `assetsInlineLimit`；
  新增 `src/assets.d.ts` 声明 `*.png` 导入到的是 data URI 而非文件路径。

- `vendor/engine` 与 iJipu 引擎**逐文件哈希一致**（33 个文件，含新增/删除两侧核对，差异为 0）。
- `main.js` 逐项核对：**7 枚图标与 `vendor/icons/` 的 data URI 完全一致**、`data:image/png;base64,`
  恰好 7 处、**无任何运行时图标路径残留**。

# 爱记谱 iJipu 0.9.1

> 本版随 `@ijipu/engine`（0.12.0 → **0.13.0**）同步 **6 个引擎文件**：新增「谱面设置行校验」，
> 并带来几个可选的新 API。**插件的试听口径不变——仍然按谱面音色演奏**
> （曲内 `@乐器名@` > 描述头 `Y:`（按声部）> 默认音色/自动），无需改笔记里的任何写法。

## 新增：谱面设置行有问题时会给出提示

- 谱面末尾的 `# jps-config:{...}` 若是**坏 JSON**、**值类型不对**（如 `"margin_left":"abc"`）、
  **键名拼错**（如 `margin_laft`）或**整行被缩进**（必须顶格），现在会以**带行号**的告警出现在
  插件的问题提示里，并附「正确写法」。
- 此前这类问题一律**静默**处理：坏 JSON 让整行设置失效、坏值直接生效、拼错的键被丢弃，
  用户只看到「设置莫名不生效 / 退回默认」。现在不合法的那一项会被忽略并回退（**谱面照常渲染**），
  只有 JSON 整行坏掉才整行忽略。

## 引擎同步（不改变插件试听口径）

- **设置读取端类型校验**：`inspectJpsConfig` / `inspectJpsConfigLine`（引擎 `settings.ts`），
  解析器把设置行告警并进 `ParseResult.errors` —— 插件的问题提示区直接受益（告警不阻断渲染）。
- **写回只固化用户改动**：新增 `mergeConfigEdits(code, base, next)`；`writeJpsConfig` /
  `roundPxIntegers` 的入参放宽为 `Partial<PageConfig>`。插件「保存到谱面」写的仍是整份配置，行为不变。
- **试听「全篇音色」是可选参数**：`buildPlaySequence` 新增第 6 参数 `instrumentOverride`，
  并新增 `gmVoiceRef(program)` / `countScoreInstrumentSwitches(result)`。
  **插件不传该参数 ⇒ 试听依旧按谱面音色**；这与 iJipu 应用「选定具体音色 = 全篇统一」是**两套口径**
  （应用侧口径详见其 v0.22.0 的 `CHANGELOG.md`）。
- `inferBpm` 无 `J` 时的默认速度注释修正（实际为 **70**，此前注释误写 90）。

## 验证

- 插件 `npm run smoke`：**149 项全绿**（`tsc -noEmit -skipLibCheck` 通过）。
- `vendor/engine` 与 iJipu 引擎**逐文件哈希一致**；本次同步 6 个文件：
  `index.ts`、`settings.ts`、`parser/parser.ts`、`playback/{gmVoices,index,sequence}.ts`。
- 应用侧同批：`npm run smoke` 首次 **0 失败**（旧的「18 条预存失败基线」已逐条清理归零）。

# 爱记谱 iJipu 0.9.0

> 本版随 `@ijipu/engine`（0.11.0 → **0.12.0**）同步 **21 项引擎改动**，并修好插件侧试听的三处口径问题。
> 主题：**把临时伴奏 `{bz … }` / 临时多声部 `{dsb … }` 打磨到可用**，以及**多声部试听让每个声部真正用上自己的音色**。
> 插件侧不需要改笔记里的写法——原来怎么写的谱子，现在会显示得更准、听得更对。

## 改进：试听色块与应用完全一致（adj452）

- **逐声部逐块**：色块按「曲行 + 声部 + 音色 + 声部角色」分别绘制——多声部各声部一块、
  `{bz … }` 重叠区与 `{dsb … }` 上下两层**各有各的色块并同步移动**（此前每行只画得出一块）。
- **高度按谱面几何**：优先使用引擎按曲行几何算出的上下边界（多声部按**声部中线**分块、
  临时段按**上下层中线**分块），色块不再互相覆盖、也不再往歌词方向压。
- **配色按声部角色/音色**：`{bz}` 上层 = 蓝（伴奏）、`{dsb}` 下层 = 绿（第二声部）、
  `{dsb}` 上层 = 红（主声部）；普通旋律按**音色**着色（同一音色恒定同色，`@乐器名@` 切换音色时颜色跟着变）。
- **多组多声部时色块跑到第一组位置**——已修：一页里有好几组多声部时，第 2 组及之后的色块
  不再跳到第 1 组那一行。

## 修复：多声部试听「只响一种音色」（两条根因）

1. **播放通道按「乐器族」分配**：同族的两个音色（钢琴+电钢琴、小提琴+大提琴、长笛+竖笛…）会撞在
   同一条 MIDI 通道上，后设的音色把先前声部一起改掉，且已设过的音色不会再补发 ⇒ 整首只剩一种音色
   （实测 17 个事件里 11 个用错音色）。现在**一个音色独占一条通道**，并跳过 GM 打击乐通道
   （`9 钢片琴` 这类音色不再走样）。
2. **音色名解析表不完整**：`Y:` / `@乐器名@` 写「设置 → 音色库」列表里的名称，此前 **128 个名称里有 101 个
   解析不到自己的音色**（例如「弦乐合奏1」「弦乐合奏2」都变成同一个 48，「高音/中音/次中音/低音萨克斯」
   都变成 65）。现在音色表收敛为引擎唯一来源，列表里的**任意名称**都能解析，也支持列表里的**编号**写法（`Y: 21`）。
   > 注意一处行为变化：`Y: 电钢琴` 由旧口径的 4 改为按列表口径 **2**（GM 标准：2 是电钢琴、4 是电钢琴1）。

## 变更：「默认音色」不再压掉伴奏与曲内 `@乐器名@`（adj450）

- 设置里的「默认音色」只在**谱面没有显式指定**时生效：**伴奏/第二声部**（`{bz}`/`{dsb}` 重叠区）与
  曲内 `@乐器名@` 一律保留自己的音色（与 iJipu 应用同口径）。
- 设置项说明补上覆盖关系：**选了具体音色会覆盖谱面里的 `Y:` 乐器**——要按谱面各声部音色演奏，请选「自动」。
  （默认就是「自动」。）

## 同批引擎修复（随本版一起生效）

- **`{bz}` / `{dsb}` 段内音符的光标联动**、**段层与主旋律逐拍对齐**、**段内内容/末音丢失**、
  **段层色块左右边界**（段内小节线为硬上限、`{bz}` 以前后小节线为界、`{dsb}` 以大括号为界、
  首个色块从起始音符开始、末音延伸到段层右界）、**`&zkh` 位置**、**倚音音色**、**重叠区占宽**、
  **临时段上下层间距可调**（谱面 `segmentRowGap`，缺省 22px）等。
  逐条说明见 iJipu 应用 v0.21.0 的 `CHANGELOG.md`。

## 验证

- 插件 `npm run smoke`：**149 项全绿**（本版新增 30 项断言：音色口径 8 + 色块规则 16 + 透传 6）；
  `tsc -noEmit -skipLibCheck` 通过。
- `vendor/engine` 与 iJipu 引擎**32 个文件逐文件哈希一致**（本次同步 13 个文件，新增
  `playback/channels.ts` 与 `playback/gmVoices.ts`）。
- 应用侧：`tsc -b` + `npm run build` 通过；`npm run smoke` 失败项 **18 == 已知基线**；
  `preview:render` 7 个示例谱全部 `errors=0`。

# 爱记谱 iJipu 0.8.0

> 本版随 `@ijipu/engine`（0.10.4 → **0.11.0**）同步一项**新语法**：**临时伴奏 `{bz … }`** 与
> **临时多声部 `{dsb … }`**。插件侧不需要改代码，只是引擎换新版——笔记里可以直接写这两种语法了。
>
> 用途：**一段旋律里临时加一层伴奏、或临时分成两个声部**，不必把整首曲子都改成多声部。
> 用 `{bz … }` / `{dsb … }` 直接写在曲行中间，段与主旋律**同拍位对齐**、谱面正确显示。

## 新增：临时伴奏 `{bz … }` 与临时多声部 `{dsb … }`（adj427）

- **`{bz … }` 临时伴奏**：段内容是**伴奏声部**，画在主旋律**上方**、与主旋律同一拍位**垂直对齐**。
- **`{dsb … }` 临时多声部**：段内容是**主声部**；该段覆盖范围内的主旋律自动成为**第二声部**，
  两层上下叠放、同一拍位对齐，并用一对大花括号 `{ }` 把两层括在一起。
- **叠加段不占主旋律拍位**：`{ … }` 前后主旋律的拍位连续不变；段宽 = `[段所在拍位, 段所在拍位 + 段自身总拍数)`。
- **括号两种写法任选**：段内不写 → 程序给整段加一对圆括号；段内自己写 `&zkh` / `&ykh` →
  按你写的位置绘制并**预留占宽**（不要两种同时用，否则会出现两层括号）。
- 段内可正常写音符、时值、小节线；段必须**成对闭合**、**不支持嵌套**（写错会给出明确报错与正确写法）。

```jps
V: 1.0
B: 临时伴奏示例
D: C
P: 4/4
Q: 3 4 | {bz 1 2 3 4 | 5 6 7 1'} 5 6 7 1' | 1' 7 6 5 | 5 5
```

## 试听：两个声部各用各的音色

- **`{bz … }`**：上层（段内容）= **伴奏声部** → 第 2 可用音色（脚本第 2 条 `Y:` 行；没有则「手风琴」）、
  力度 **0.75**；下层（包络内主旋律）= **主声部** → 音色与力度**完全不变**。
- **`{dsb … }`**：上层 = **主声部**（该曲行音色、力度 1）；下层 = **第二声部**（第 2 可用音色、力度 **0.75**）。
- 段层与主旋律**同一拍位同刻发声**；落在 `|: … :|` 里时**每一遍都会演奏**。
- **播放色块按音色着色**：不同音色不同颜色；重叠区**上下两层各一个色块、同步移动**。
  （既有单声部仍是红块、Q1 红 / Q2 蓝，观感不变。）
- 插件侧「试听音色」的全局覆盖只作用于**主声部**，不会把重叠区两个声部压成同一种音色。

## 文档

- 插件内帮助所引用的 `docs/SYNTAX.md`（《脚本语法说明》）新增 §2.12 介绍这两种语法
  （写法、两种括号、对齐与宽度规则、试听声部与音色、限制），可在 iJipu 应用内「帮助 → 脚本语法说明」查看。

## 验证

- 引擎 `npm run smoke`：失败项 **18 == 已知基线**（零新增），1450 条断言通过；本轮新增 100+ 条。
- 插件侧 `tsc -noEmit -skipLibCheck` 通过；`vendor/engine` 与 `ijipu` 引擎**逐文件哈希一致**
  （本次新增 `layout/segments.ts`，另同步 8 个文件）。
- 应用侧 `npm run preview:render` 7 个示例谱全部 `errors=0`（**无段谱面的几何零影响**）。

# 爱记谱 iJipu 0.7.5

> 本版随 `@ijipu/engine` 同步两项**排版行为**变更（插件侧不需要改代码，只是引擎换新版）：
> ① **短谱不再挤在左边**——一段曲部**只有一行**时（比如只写了一句的谱例），若小节数少于「两端对齐最小小节数」
> （默认 4），整行按该数**预分小节槽**：每小节占一个槽、槽内音符自动摊开，行尾留白；
> 某小节内容实在放不下时，这一小节按自身自然宽度排开、不挤压。
> ② **左右边距默认 40 → 50px**——没在谱面里显式写过边距的笔记，打开后左右留白会比以前宽一些
> （显式写过 `margin_left/margin_right` 的笔记不受影响）。

## 变更：单行曲部按「小节槽」预分占宽（adj421）

- **现象**：只写一到三小节的短谱（插件里常见的"一句谱例"）整行挤在左边一小块里，右边一大片空白；1 小节的 `Q: 1 2 3 4 |` 尤其明显。
- **改法**：**只有一行的曲部**且小节数少于「两端对齐最小小节数」（默认 4）时，整行占宽按该值**预分小节槽**（槽宽 = 行内容宽 ÷ 4）——每小节领一个槽、槽内音符按空间优先摊开；若某小节「本体宽 + 小节线占位」超过槽宽，则该小节保持自然宽（不压缩）。
- **效果**：1 / 2 / 3 小节的单行曲部分别占行宽的 1/4、2/4、3/4，行尾留白；单行 1 小节的每小节几何与「4 小节铺满行」里的一个小节**完全一致**。多行曲部不受影响（末行仍按"对齐前面行"的规则）。

## 变更：左右边距默认 40 → 50px（adj418）

- 没在谱面 `# jps-config` 里写过边距的笔记，渲染时左右留白变宽（每侧多 10px），行内容相应收窄。
- 写过 `margin_left` / `margin_right` 的笔记**不受影响**（显式值优先）。
- 想改回去：在插件设置或谱面设置里把左右边距调回 40 即可（会写进该笔记的 `# jps-config`）。

## 验证

- 引擎 `npm run smoke`：新增 `[106]`「单行曲部小节槽」**两种布局各 8 条**断言（1/2/3 小节的槽位、槽内摊开、本体超槽 → 自然宽、多行曲部不适用），并把受影响的既有几何断言按新规则重算；失败项 17 == 改动前基线。
- 插件侧 `tsc -noEmit -skipLibCheck` 通过；`npm run smoke` **119 项全绿**；`vendor/engine` 与 `ijipu` 引擎**逐文件哈希一致**（本次同步 `types.ts` 与 `layout/index.ts` 两个文件）。
- 应用侧无头 Chrome 实测：1 小节的每小节几何 == 4 小节铺满行的第 1 小节（音符 x 逐一相同）、2 小节的小节间距 = 一槽宽，并截图目视。

# 爱记谱 iJipu 0.7.4

> 本版随 `@ijipu/engine` 同步 **adj413**：**谱面设置里的 px 值一律整数**。
> 插件侧（以及应用侧）过去把「虚线拖拽的浮点位移」原样写回 `# jps-config`，
> 于是笔记里会出现 `"margin_top":40.4`、`"metaPos":{"title":{"x":10.5}}` 这类小数
> ——描述头位置更是刻意保留 0.1px 精度。现在引擎在**读取与写入两端都取整**，
> 旧笔记里的小数值**打开即归整**，不需要手动清理。插件侧不需要改代码，只是引擎换新版。

## 修复：页面设置里的 px 值会出现小数（adj413）

- **现象**：拖动排版辅助虚线、或改过「页面设置」之后，笔记里的 `# jps-config` 会带上 `"margin_top":40.4`、`"note_size":13.49`、`"metaPos":{"title":{"x":10.5}}` 这类小数；反复微调还会不断累积零碎数值。
- **根因**：虚线拖拽的落点是「鼠标位移 ÷ 预览缩放」的浮点结果，写入时**原样落盘**；读取端也不做归整，于是这些小数被一直沿用（`metaPos` 甚至按 0.1px 精度刻意保留）。
- **修复**：引擎 `settings.ts` 新增 `roundPxIntegers()`，在**读取端**（`mergeJpsConfig`，即打开/合并谱面设置时）与**写入端**（`writeJpsConfig`，即保存时）双向取整——覆盖顶层数值、按页行距 `heights`、描述头 `metaPos.x/y`；应用侧的虚线拖拽落点与设置输入框步长同步改为整数步进（插件侧无需改动）。
- **兼容**：取整**幂等**，对非数值字段（字体栈、枚举、布尔）**不做任何改动**；旧笔记里的小数在**读取时即归整**、保存时才落盘，不会造成额外改动。

## 验证

- 引擎 `npm run smoke` 新增 **22 条 adj413 断言**（新建模板的两条分隔注释恰好 30 字符 + 正文后留白 + 尾部页面设置区块原地更新；`roundPxIntegers` 对顶层/`heights`/`metaPos` 取整、幂等、默认配置全为整数、读写两端落盘均为整数）；失败项 17 == 改动前基线。
- 插件侧 `tsc -noEmit -skipLibCheck` 通过；`npm run smoke` **119 项全绿**；`vendor/engine` 与 `ijipu` 引擎**逐文件哈希一致**（29 个文件 0 处不一致，本次同步 `settings.ts` 与 `index.ts` 两个文件）。
- 应用侧另用无头 Chrome 实测：注入带小数的 `# jps-config`（`margin_top:40.4`、`heights:[12.4,8.5,20.5,0.5]`、`metaPos.x:10.5` 等）后读回，页面设置对话框显示的全是整数、无一处小数。

# 爱记谱 iJipu 0.7.3

> 本版随 `@ijipu/engine` 同步 **adj411**：修**附点音符的减时线在附点前断掉**——
> `1//2/.` 这类附点写在一拍后半的谱子，`2` 的减时线原来止于数字右缘就断了，
> 而附点是画在数字右侧的，看起来像"线少了一截"。现在带附点的音符，减时线会**延伸到附点之下**。
> 插件侧不需要改代码，只是引擎换新版。

## 修复：附点音符的减时线延伸到附点之下（adj411）

- **现象**：`1//2/.`（`2` 带附点）里 `2` 的减时线只画到数字右缘，附点下方是空的，水平方向"看起来断了一截"；同一小节里写成 `1//2/`（无附点）反而正常。
- **根因**：减时线（`computeBeams`）的右端一直是常量「末个音符的数字右缘」，与附点无关；而附点画在**数字右侧**（占该音符时值宽度的后半），于是带附点的音符天然"线比音符短"。
- **修复**：组尾音符带附点时，线尾取 `max(数字右缘, 末附点右缘)`。附点的圆心与右缘几何同时抽成 `dotCenterXOf` / `dotRightEdgeOf`，**与附点绘制共用同一份**，避免"渲染一套偏移、别处再算一套"的漂移（这类教训本项目已吃过：E-2026-129）。
- **不受影响**：不带附点的音符仍止于数字右缘（不误伸）；附点写在拍首时（`2/. 1//`）附点本就在线内，无多余变化。

## 验证

- 引擎 `npm run smoke` 新增 **5 条 adj411 断言**（**空间优先与时值优先两种布局各验一遍**）：带附点的减时线越过数字右缘、右端等于末附点右缘、以及"无附点不误伸"的反例；失败项 17 == 改动前基线。
- 截图目视核对四个用例：`1//2/. 3 4`（两种布局，线均延伸到附点下）、`1//2/ 3 4`（对照，不误伸）、`2/. 1// 3 4`（附点在拍首，无多余变化）。
- 插件侧 `tsc -noEmit -skipLibCheck` 通过；`vendor/engine` 与 `ijipu` 引擎逐文件哈希一致（29 个文件 0 处不一致）。

# 爱记谱 iJipu 0.7.2

> 本版修移动端「**点「✎ 源码」后，源码框下方空出一大截（约一个键盘的高度）**」——
> 输入法弹出后源码框没有填满可视区，看起来像"被多缩了一次"。
> 真凶**不在键盘高度上**，而在宿主的两处样式：
> ① `.workspace-leaf-content .view-content { padding-bottom: max(var(--safe-area-inset-bottom), …) }`
> —— 真机上该变量等于**键盘高**（实测 319 = `--keyboard-height`），于是容器内容盒子正好矮一个键盘高；
> ② `textarea { height: 100%; min-height: 50vh; max-height: 20vh|80vh }` —— 会盖掉"撑满"的高度赋值。
> 现在对这两处逐条用 inline + `!important` 反制，并按**实测位置**算出源码框高度（可视区底 − 源码框顶）。
> 另外设置页补上了**构建指纹**，便于判断设备上装的到底是哪一份构建。

## 修复：源码框下方空出约一个键盘的高度（adj404 / adj408 / adj409）

- **现象**（用户真机反馈，多轮复现）：输入法未打开时源码框满屏正确；一打开输入法，源码框下方空出一大截，
  空出的高度约等于一个键盘。
- **定位过程**（真机读数，非推断）：先按"视口会不会随键盘缩"两条路都试过（`visualViewport` / `min(vv, innerHeight)`），
  在用户机上视口**根本不缩**（`innerH=vvH=914`），故这条路无效；随后在源码视图里加了一行临时诊断输出
  （`appC=595`、`box=502`、`ta=119`、**`padB=319`**），一步定位：
  - `appC=595` = `914 − 319` → Obsidian 自己的容器高度**正确**（只扣一次键盘）；
  - `box=502` = 容器高度也**正确**（顶部文件头 93 + 502 = 595 = 键盘上沿）；
  - **`padB=319`** → 容器自身的 `padding-bottom` 正好等于键盘高，内容盒子因此少了一个键盘高；
  - `ta=119` → 还叠加了宿主 `textarea` 的 `height/min-height/max-height` 规则把高度赋值盖掉。
- **修复**：
  1. **反制宿主的键盘内边距**（`adj409`，真凶）：容器上 inline `padding-bottom: 8px !important`
     ——容器高度已按可视区钉好，不需要宿主那段留白；
  2. **反制宿主 textarea 规则**（`adj408`）：源码框上 inline `flex:0 0 auto` / `min-height:0` /
     `max-height:none` / `height`（按实测算）全部 `!important`，样式文件里再按类名压一层作双保险；
  3. **容器尺寸同样用 inline important 钉死**（`height` / `display:flex` / `flex-direction` /
     `overflow:hidden` / `max-height:none` / `position:relative`），不再依赖 CSS 级联；
  4. 高度**实测**：先 `height:auto` 复位 → 量源码框真实顶部 → 高度 = 可视区底 − 源码框顶 − 内边距；
  5. 键盘高度仍按双信号补偿（`min(innerHeight, visualViewport 底) − 未扣足的键盘高`），并在需要时
     临时解除 `.app-container` 的 `max-height`；切走 / 关闭 / 重画时逐条还原，不留副作用；
  6. 桌面端不挂载这套逻辑（`Platform.isMobile` 判定），行为完全不变。
- **结果**：源码框从工具条一直延伸到键盘上沿，内容填满、滚动条正常（用户真机确认）。

## 新增：设置页显示构建指纹（adj407）

- 设置页头部显示 **`版本 v0.7.2 · 构建 2026-09-14 23:48 @cc88804e · 作者 蜗牛🐌`**。

## 验证

- 用户真机逐轮读数确认：修复前 `padB=319 / ta=119`（源码框下方空一个键盘高）→ 修复后源码框填满到键盘上沿 ✓。

# 爱记谱 iJipu 0.7.1

> 本版修移动端「**切到源码后窗格缩两次、还填不满窗口**」——手机上一打开源码编辑，
> 键盘弹出缩一次、紧接着又缩一次，而且缩完之后并没有占满可用高度。
> 根因是两套尺寸机制在打架：视图容器自己会滚（`height:100%` + `overflow:auto`），
> 源码框又写死了 `min-height: 240px`；键盘/移动端工具栏先后改变可用高度时，
> 两者叠加就表现为"缩两次"，且收缩后不等于"窗口剩余高度"。
> 现已改为：**源码框永远等于窗口剩余高度**，容器自己不再滚动。

## 修复：`✎ 源码` 窗格缩两次、不填满窗口（adj402）

- **现象**（用户反馈，移动端）：在 `.jps` 文件视图里点「✎ 源码」——输入法刚打开时源码窗格先变小，
  接着**又进一步缩小**；后一次缩小没有必要，且窗格没有占满可用空间。
- **根因**：`.ijipu-file-view` 用 `height:100%` + `overflow:auto`（自己会滚动），
  `.ijipu-source-editor` 又写了 `flex:1 1 auto` + `min-height:240px`（硬下限）。
  可用高度被键盘改变时，容器滚动与内容收缩两套机制叠加，于是出现二次缩小，
  且 `240px` 下限让窗格在矮视口下不再等于"剩余高度"。
- **修复**：
  1. 视图容器 `flex` 列 + `min-height:0` + `box-sizing:border-box`——允许随父级一起收缩；
  2. 源码态给容器加 `.ijipu-file-editing` → 容器**不自己滚动**（`overflow:hidden`），滚动交给源码框，
     避免两套机制叠加；
  3. 源码框去掉 `240px` 硬下限（`min-height:0`）+ `flex:1`——**永远等于窗口剩余高度**；
     桌面端仍保留 `resize: vertical` 手动拉高。
- **顺带**：文件级工具条固定为 `flex:0 0 auto`，不会被源码框挤压换行。
- **注**：本版并未真正修好真机表现（用户在 0.7.2 的验证阶段指出源码框下方仍空出约一个键盘的高度），
  真凶在宿主的 `padding-bottom` 与 textarea 规则上，见 0.7.2 的 adj408/adj409。

## 验证

- 插件 `npm run smoke` 新增 **4 条断言**（第 12 节：容器 `height:100%+min-height:0+border-box`、
  源码态容器 `overflow:hidden`、源码框无 `240px` 硬下限且 `flex:1`、`fileView.ts` 确实加了
  `.ijipu-file-editing` 类）——**共 112 项全绿**。
- `tsc -noEmit -skipLibCheck` + `npm run build` 通过；`main.js` 为构建产物、不入库。
- 引擎未变动（本版只改插件侧 CSS/视图），因此 `vendor/engine` 与 0.7.0 一致。

# 爱记谱 iJipu 0.7.0

> 本版两件事：**设置页补上版本与作者信息**（插件自身），以及随 `@ijipu/engine` 同步 **adj397 / adj398**
> ——前者修减时线"该连没连"，后者修带临时拍号的行"撑破右边距"。
> 引擎侧不需要插件改代码，同步 `vendor/engine` 即可；插件自己的改动只有设置页头部。

## 新增：设置页显示版本与作者（插件侧）

- 设置页标题「爱记谱（iJipu）」下方补一行 **`版本 v0.7.0 · 作者 蜗牛🐌`**。
- 版本号取自 `manifest.json`（`this.plugin.manifest`），**不硬编码**——发版只改 manifest，设置页自动跟着变，
  不会出现"设置页写的版本和实际装的不一致"。
- 作者名在 manifest 有 `authorUrl` 时渲染为可点击链接（新标签打开），没有则降级为纯文本；
  同时给 `manifest.json` 补上 `authorUrl` 指向本仓库。
- 样式新增 `.ijipu-settings-meta`（`var(--text-faint)` 弱化显示、链接 hover 用强调色），深浅主题都跟随主题变量。

## 修复：减时线不再被连音组边界切断（引擎 adj397）

- **现象**：4/4 的 `2/. 3// 5/ (y5// 6// 5//) 3[2/] 0// 2// 3// 5// |` 里，`5/` 与 `(y5// 6// 5//)`
  **同在第 2 拍**，但 `5/` 的减时线是孤立一小段，与组内三音的横线断开。
- **根因**：减时线的分组键是"有连音组号就按组号、否则按拍"，**组号被当成互斥依据**——
  连音组成员与同拍的组外音符永远落在两个桶里，即使同拍也不会共用横线。
- **修复**：分组改为**相邻逐对判定**——① 同属一个等时值连音组 → 相连（跨拍也不断开，保留上一版规则）；
  ② 否则只要**在同一拍内** → 相连。现在 `5/` 与组内三音共用第 1 条减时线，
  第 2 条仍只覆盖带 `//` 的组内三音；跨拍连音组仍整组一条、且不并入相邻拍的音符。

## 修复：带临时拍号的行不再撑破右边距（引擎 adj398）

- **现象**：一行里写了 `|"p:2/4"`（临时节拍）时，整行内容**越出右边距**——左右边距 40、音符字号 13 下实测
  越界 **19.2px**（相当于每个临时拍号分数约 10.7px）；行末小节线带拍号时，**分数本身**还会单独越界 12px。
- **根因**：临时拍号分数画在小节线**右缘之后**，而空间优先布局的**行宽预算**只按 `barlinePad×2` 计小节线、
  **放置处**却按分数整宽撑开——两套算法不一致，差出来的宽度无人买单，音符按虚高的可分配宽摊开。
- **修复**：新增纯函数 `meterGapRight()`，让**预算与放置同源**（无分数时与原式完全等价，既有排版零影响）；

# 爱记谱 iJipu 0.6.0

> 本版随 `@ijipu/engine` 同步 **adj395 / adj396**，修的是两类「看起来能显示、其实时值算错」的问题：
> ① **等时值连音组 `(y …)`** 以前按各自写的减时线时值算，`3./ 6,// (y3/ 2/ 1/)` 里三个音被当成 1.5 拍
> ——越出小节、拍位漂到下一拍、**减时线被拍线切断**；现在组占「这一小节剩下的那一截时值」，
> 占宽同样按剩拍分摊，**减时线连成一条**（跨拍也不断开）并标数字。
> ② **倚音**以前**不占主音符时值**（时值写死 1/8 拍，前倚音借前一个音符的时间、后倚音借后一个音符的时间），
> 后倚音还一律画在数字右侧、压住增时线/附点；现在倚音**从主音符内部切时值**，并新增
> **增时线/附点之后写后倚音**（`3 -[h5/]`）——谱面上画在 `-` 之后，演奏时主音符先奏满、最后一小段才是倚音。
> 插件侧不需要改代码，只是引擎换新版；得益于上一版「告警不阻断渲染」，新增的语法告警也只会提示、不会影响显示。

## 改进：等时值连音组 `(y …)` 的时值、占宽与减时线（adj395）

- **规则**：组总时值 = **小节名义拍数 − 组外音符实际时值**（就是"这一小节里剩下的那一截"）。
  例：2/4 的 `3./ 6,// (y3/ 2/ 1/) |` —— `3./`（0.75 拍）+ `6,//`（0.25 拍）已占 1 拍，
  所以组占**剩下的 1 拍**，组内三音**各 1/3 拍**（演奏时值也是 1/3 拍）。
- **占宽同样按"剩余时值"分摊**：组内每个音符的占宽 = 组总占宽 ÷ 音符数（不再按各自写的 `/` 时值算成 1.5 拍）。
- **减时线连成一条**：一个三连音/多连音就是一个连音组，**跨拍也不断开**，也不与同一拍内的组外音符共线；
  弧线上方标出组内音符数。
- **修的两个根因**：① 空间优先布局专用的时值拆分不认连音组的覆盖时值（拍级路径本来是对的，所以只有默认布局错）；
  ② 减时线的分组键只有"拍"，跨拍连音组的第 3 个音会被拍线甩出去。现在给连音组打了**解析期生成的稳定组号**，
  渲染只消费，不再依赖几何位置推断。

## 新增：增时线/附点之后的后倚音（adj396）

- **写法**：`3 -[h5/]`（等价 `3-[h5/]`）、`3.[h5/]`（等价 `3 .[h5/]`，独立附点归前音符）。
- **演奏**：主音符总时值 2 拍（附点后为 1.5 拍）——主音符**先奏满增时线/附点**（奏到末尾前），
  **最后 1/4 拍**才奏后倚音；总时值不变。
- **谱面**：倚音画在**增时线/附点之后**（紧靠这些元素），弧线随之落在其后。
  无增时线也无附点的后倚音仍紧贴数字右上角（既有观感不变）。

## 修复：倚音不再向相邻音符"借时间"（adj396）

- **现象**：`3[2/]` 听到的是「1/8 拍硬的倚音 + 整 1 拍主音符」，不是「1/4 拍倚音 + 3/4 拍主音符，合计 1 拍」；
  前倚音会挤占前一个音符的尾巴、后倚音会挤占后一个音符的开头，整曲被撑长。
- **规则**：单个倚音实际时值 = **`1/2^(括号内减时线条数 + 1)` 拍**（写 `2[3/]` → **1/4 拍**＝实音符的 `2//`，
  "再减一半"；与"倚音减时线条数 = 书写条数 + 1"的显示规则自洽）。主音符发声时值 = 总时值 − Σ倚音时值。

  | 写法 | 演奏 | 谱面 |
  |---|---|---|
  | `3[2/]` 前倚音 | 先 1/4 拍倚音 2，再 3/4 拍主音符 3，合计 1 拍 | 倚音在数字左上角 |
  | `3[h2/]` 后倚音 | 先 3/4 拍主音符 3，最后 1/4 拍奏倚音 | 紧贴数字右上角 |
  | `3[3/2/]` 多倚音 | 1/4 + 1/4 倚音，主音符余 1/2 拍 | 依次左排 |
  | `3 -[h5/]` / `3.[h5/]` | 主音符先奏满（1.75 / 1.25 拍），末段 1/4 拍奏倚音 | 画在增时线/附点之后 |

- **新增告警**：倚音总时值超过主音符时值（此时主音符会被钳制为 0 拍、不发声），并给出正确写法。
- **连带修复**：连音线内的同音连奏合并此前会把长音**并到倚音事件**上（后倚音事件排在主音符之后），
  现改为按主音符事件合并，并规定带倚音的音符不参与合并。

## 验证

- 引擎 `npm run smoke` 新增 **35 条断言**（连音组 14 + 倚音 21），全绿；失败项 17 == 改动前基线。
- 两处新规则都按**空间优先（默认）与时值优先两种布局**各断言一遍（此前只测非默认的时值优先，等于没测）。
- 无头 Chrome 截图核对：`3./ 6,// (y3/ 2/ 1/) |`（三音一条减时线 + 上方数字 3）、跨拍组、`(y1 2 3) 4 |`、
  `3[2/]`、`3[h2/]`、`3[3/2/]`、`3 -[h5/]`（两种布局）、`3.[h5/]`（两种布局）、`3[h5/]` 基线均正确。

- **背景**：插件设置与笔记 frontmatter 里的 `ijipu_*` 是**默认层**，只对"`.jps` 里没写的项"生效，
  且**不随谱走**。于是把一份谱复制给别人时，对方看到的是"**他的**默认层 + 谱面"，与你的可能不同。
- **新增徽标提示**：当"当前生效的设置"里有某项来自插件设置 / frontmatter、而谱面 `# jps-config`
  并没有写时，工具条显示「**未随谱携带 N 项**」，点开即可查看是哪些项、并一键随谱固化。
- **「随谱固化（分享用）」按差量写**：把与引擎默认值不同的**全部生效项**写进谱面 `# jps-config`
  （只写差异项，不再整体全量落盘），与应用的「保存设置」口径一致；固化后徽标归零。
- **拖拽写回只写本次改动**：预览里拖动虚线（行距 / 声部间距等）后，只把**本次真正改动的项**
  合并进谱面，不会把你本机默认层里的其它项一起"顺带"写进别人的谱。

## 同步的引擎改进（`@ijipu/engine` 0.13.2 → 0.14.0）

- **多声部里「无时值但有占宽」的元素显示不对**（`adj479`）：`&zkh` / `&ykh` / `&hx`
  此前在多声部块内**算进了拍宽却从不绘制**（写了等于没写、空位照留），滑音 `&shy` / `&xhy`
  布局端完全不占宽（每拍紧密排布时会压到后一个数字），附点也会压字。现在：标记按源码位置
  **插位**（拍首做成该拍的前置占位、各声部取最大值 ⇒ 同拍数字仍纵向对齐），滑音的**墨迹宽度**
  计入音符本体宽，音符本体宽**逐拍归位**（附点、增时线、尾部倚音各归各拍）。
- **声部间距（`height_shengbu`）可调负数**（`adj479`）：范围由 `[0, 300]` 放宽到 `[-30, 300]`，
  需要把声部往紧里压时不再卡在 0（预览里那条虚线也拖得动负数了）。
- **新增 `configCarryover()`**（`adj480`）：给出"生效值 ≠ 默认值、但谱面没写"的字段清单——
  上面的徽标就是用它算出来的。
