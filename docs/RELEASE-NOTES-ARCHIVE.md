# 爱记谱 iJipu 0.7.0

> 本版两件事：**设置页补上版本与作者信息**（插件自身），以及随 `@ijipu/engine` 同步 **adj397 / adj398**
> ——前者修减时线"该连没连"，后者修带临时拍号的行"撑破右边距"。
> 引擎侧不需要插件改代码，同步 `vendor/engine` 即可；插件自己的改动只有设置页头部。

## 新增：设置页显示版本与作者（插件侧）

- 设置页标题「爱记谱（iJipu）」下方补一行 **`版本 v0.7.0 · 作者 蜗牛🐌`**。
- 版本号取自 `manifest.json`（`this.plugin.manifest`），**不硬编码**——发版只改 manifest，设置页自动跟着变，
  不会出现"设置页写的版本和实际装的不一致"。
- 作者名在 manifest 有 `authorUrl` 时渲染为可点击链接（新标签打开），没有则降级为纯文本；
  同时给 `manifest.json` 补上 `authorUrl` 指向本仓库。
- 样式新增 `.ijipu-settings-meta`（`var(--text-faint)` 弱化显示、链接 hover 用强调色），深浅主题都跟随主题变量。

## 修复：减时线不再被连音组边界切断（引擎 adj397）

- **现象**：4/4 的 `2/. 3// 5/ (y5// 6// 5//) 3[2/] 0// 2// 3// 5// |` 里，`5/` 与 `(y5// 6// 5//)`
  **同在第 2 拍**，但 `5/` 的减时线是孤立一小段，与组内三音的横线断开。
- **根因**：减时线的分组键是"有连音组号就按组号、否则按拍"，**组号被当成互斥依据**——
  连音组成员与同拍的组外音符永远落在两个桶里，即使同拍也不会共用横线。
- **修复**：分组改为**相邻逐对判定**——① 同属一个等时值连音组 → 相连（跨拍也不断开，保留上一版规则）；
  ② 否则只要**在同一拍内** → 相连。现在 `5/` 与组内三音共用第 1 条减时线，
  第 2 条仍只覆盖带 `//` 的组内三音；跨拍连音组仍整组一条、且不并入相邻拍的音符。

## 修复：带临时拍号的行不再撑破右边距（引擎 adj398）

- **现象**：一行里写了 `|"p:2/4"`（临时节拍）时，整行内容**越出右边距**——左右边距 40、音符字号 13 下实测
  越界 **19.2px**（相当于每个临时拍号分数约 10.7px）；行末小节线带拍号时，**分数本身**还会单独越界 12px。
- **根因**：临时拍号分数画在小节线**右缘之后**，而空间优先布局的**行宽预算**只按 `barlinePad×2` 计小节线、
  **放置处**却按分数整宽撑开——两套算法不一致，差出来的宽度无人买单，音符按虚高的可分配宽摊开。
- **修复**：新增纯函数 `meterGapRight()`，让**预算与放置同源**（无分数时与原式完全等价，既有排版零影响）；
  行末小节线的右钳制也让出分数占位。修复后该行右缘正好贴住右边距。
- **顺带排除**：`&yc` / `&zkh` / `&sby` 与越界无关（逐个删除越界量不变），问题只在临时拍号分数。

## 验证

- 引擎 `npm run smoke` 新增 **14 条断言**（`adj397` 9 条 + `adj398` 5 条）全绿；**失败项 17 == 改动前基线**。
- 减时线与右溢的断言都在**空间优先（默认）与时值优先两种布局**下各跑一遍；
  右溢按「可见内容右缘（音符 `rightX`）≤ 右边距」的端到端形式断言。
- 用户谱实测（边距 40 / 字号 13 与 18）：修复前右缘 574.5 越界 19.2px → 修复后右缘 555.3 == 右边距。
- 插件侧 `tsc -noEmit -skipLibCheck` + `npm run build` 通过、`npm run smoke` 108 passed；
  `main.js` 为构建产物、不入库（已在 `vendor/engine` 同步后重建）。
- **已知未修**：**时值优先**布局自身仍有右溢（与临时拍号无关，7.8~10.3px），默认布局不受影响。

# 爱记谱 iJipu 0.6.0

> 本版随 `@ijipu/engine` 同步 **adj395 / adj396**，修的是两类「看起来能显示、其实时值算错」的问题：
> ① **等时值连音组 `(y …)`** 以前按各自写的减时线时值算，`3./ 6,// (y3/ 2/ 1/)` 里三个音被当成 1.5 拍
> ——越出小节、拍位漂到下一拍、**减时线被拍线切断**；现在组占「这一小节剩下的那一截时值」，
> 占宽同样按剩拍分摊，**减时线连成一条**（跨拍也不断开）并标数字。
> ② **倚音**以前**不占主音符时值**（时值写死 1/8 拍，前倚音借前一个音符的时间、后倚音借后一个音符的时间），
> 后倚音还一律画在数字右侧、压住增时线/附点；现在倚音**从主音符内部切时值**，并新增
> **增时线/附点之后写后倚音**（`3 -[h5/]`）——谱面上画在 `-` 之后，演奏时主音符先奏满、最后一小段才是倚音。
> 插件侧不需要改代码，只是引擎换新版；得益于上一版「告警不阻断渲染」，新增的语法告警也只会提示、不会影响显示。

## 改进：等时值连音组 `(y …)` 的时值、占宽与减时线（adj395）

- **规则**：组总时值 = **小节名义拍数 − 组外音符实际时值**（就是"这一小节里剩下的那一截"）。
  例：2/4 的 `3./ 6,// (y3/ 2/ 1/) |` —— `3./`（0.75 拍）+ `6,//`（0.25 拍）已占 1 拍，
  所以组占**剩下的 1 拍**，组内三音**各 1/3 拍**（演奏时值也是 1/3 拍）。
- **占宽同样按"剩余时值"分摊**：组内每个音符的占宽 = 组总占宽 ÷ 音符数（不再按各自写的 `/` 时值算成 1.5 拍）。
- **减时线连成一条**：一个三连音/多连音就是一个连音组，**跨拍也不断开**，也不与同一拍内的组外音符共线；
  弧线上方标出组内音符数。
- **修的两个根因**：① 空间优先布局专用的时值拆分不认连音组的覆盖时值（拍级路径本来是对的，所以只有默认布局错）；
  ② 减时线的分组键只有"拍"，跨拍连音组的第 3 个音会被拍线甩出去。现在给连音组打了**解析期生成的稳定组号**，
  渲染只消费，不再依赖几何位置推断。

## 新增：增时线/附点之后的后倚音（adj396）

- **写法**：`3 -[h5/]`（等价 `3-[h5/]`）、`3.[h5/]`（等价 `3 .[h5/]`，独立附点归前音符）。
- **演奏**：主音符总时值 2 拍（附点后为 1.5 拍）——主音符**先奏满增时线/附点**（奏到末尾前），
  **最后 1/4 拍**才奏后倚音；总时值不变。
- **谱面**：倚音画在**增时线/附点之后**（紧靠这些元素），弧线随之落在其后。
  无增时线也无附点的后倚音仍紧贴数字右上角（既有观感不变）。

## 修复：倚音不再向相邻音符"借时间"（adj396）

- **现象**：`3[2/]` 听到的是「1/8 拍硬的倚音 + 整 1 拍主音符」，不是「1/4 拍倚音 + 3/4 拍主音符，合计 1 拍」；
  前倚音会挤占前一个音符的尾巴、后倚音会挤占后一个音符的开头，整曲被撑长。
- **规则**：单个倚音实际时值 = **`1/2^(括号内减时线条数 + 1)` 拍**（写 `2[3/]` → **1/4 拍**＝实音符的 `2//`，
  "再减一半"；与"倚音减时线条数 = 书写条数 + 1"的显示规则自洽）。主音符发声时值 = 总时值 − Σ倚音时值。

  | 写法 | 演奏 | 谱面 |
  |---|---|---|
  | `3[2/]` 前倚音 | 先 1/4 拍倚音 2，再 3/4 拍主音符 3，合计 1 拍 | 倚音在数字左上角 |
  | `3[h2/]` 后倚音 | 先 3/4 拍主音符 3，最后 1/4 拍奏倚音 | 紧贴数字右上角 |
  | `3[3/2/]` 多倚音 | 1/4 + 1/4 倚音，主音符余 1/2 拍 | 依次左排 |
  | `3 -[h5/]` / `3.[h5/]` | 主音符先奏满（1.75 / 1.25 拍），末段 1/4 拍奏倚音 | 画在增时线/附点之后 |

- **新增告警**：倚音总时值超过主音符时值（此时主音符会被钳制为 0 拍、不发声），并给出正确写法。
- **连带修复**：连音线内的同音连奏合并此前会把长音**并到倚音事件**上（后倚音事件排在主音符之后），
  现改为按主音符事件合并，并规定带倚音的音符不参与合并。

## 验证

- 引擎 `npm run smoke` 新增 **35 条断言**（连音组 14 + 倚音 21），全绿；失败项 17 == 改动前基线。
- 两处新规则都按**空间优先（默认）与时值优先两种布局**各断言一遍（此前只测非默认的时值优先，等于没测）。
- 无头 Chrome 截图核对：`3./ 6,// (y3/ 2/ 1/) |`（三音一条减时线 + 上方数字 3）、跨拍组、`(y1 2 3) 4 |`、
  `3[2/]`、`3[h2/]`、`3[3/2/]`、`3 -[h5/]`（两种布局）、`3.[h5/]`（两种布局）、`3[h5/]` 基线均正确。
- 插件侧 `tsc -noEmit -skipLibCheck` 通过；`main.js` 为构建产物、不入库。

# 爱记谱 iJipu 0.5.1

> 本版修好 **`![[xxx.jps]]` 嵌入区显示不出谱面**这个老毛病（前两版各修过一次，都没修到根上）：
> 根因是宿主 Obsidian 对"没有嵌入处理器的文件"会走一条占位兜底分支，而它的 `empty()`
> 正好把插件渲染好的谱面清掉。现在改为**向 Obsidian 注册 `.jps` 的嵌入渲染器**——
> 由宿主把渲染权交给我们，绕不开、也不再有占位块。
> 同时按反馈打磨了谱面工具栏：显示模式**改回下拉列表**（弹层用 Obsidian 自己的菜单，配色跟随主题）、
> 设置图标改为**齿轮**（与 iJipu 应用一致）、「谱面自带设置 N 项」移进设置对话框、
> 窄容器下按宽度**逐级图标化**（优先保住谱面文件名）、四个按钮的高度与宽度统一。

## 修复：`![[xxx.jps]]` 嵌入区不显示谱面（根因 + 两次误修的教训）

- **现象**：笔记里写 `![[檐下声.jps]]`，嵌入区只出现一个"写着文件名的未知嵌块"，没有谱面；同一份谱用 ```jps 代码块、或点开 `.jps` 文件视图都正常。
- **根因**（逐行核对 Obsidian 1.13.7 本体 `obsidian.asar`）：嵌入解析入口 `EmbedRegistry.load(ctx)` 的第一步是 `containerEl.empty()`，然后按扩展名找 embed creator —— `.jps` 没有，于是走 `FileEmbed` 兜底：给容器加 `file-embed mod-generic` 并塞一个文件名占位块。**用户看到的"未知嵌入块"就是它，而它那句 `empty()` 把插件先前渲染的谱面清掉了。**
- **两次误修（记在这里，避免再走回头路）**：
  1. 用 `MutationObserver`「被覆盖就重挂」——判空写的是 `container.querySelector('.ijipu-score')`（只查**后代**），而 `.ijipu-score` 恰恰加在容器**自身**上 → 永远判为"没挂上"，自我重挂瞬间耗尽重试配额，等宿主真正覆盖时已无机会。
  2. 在 post-processor 里给容器打 `is-loaded` 让宿主跳过（机制本身没错，嵌入解析只挑 `:not(.is-loaded)`）——但真机诊断日志显示：**同一个嵌入存在两个容器**，一个 `<span class="internal-embed">`（markdown 产物，post-processor 看得到），另一个 `<div class="internal-embed" src="…">`（宿主/其它方直接交给 `EmbedRegistry.load`，**完全不经 post-processor**）。只标记得到看得见的那个，可见的那个照样落到兜底分支。
- **修复**：给 `.jps` 注册 **embed creator**（Obsidian 自己的 Canvas / Bases 插件用的同一条路径）。命中后宿主不再走 `FileEmbed` 兜底 —— 无论嵌入元素是谁创建的、从哪条入口进来，渲染都必须交给我们。`app.embedRegistry` 不可用时（更老的宿主）退回 post-processor 认领作为兜底。
- **顺带**：渲染抛错时给出可见的 `⚠ 渲染失败：…`（此前只会留一片空白）；被嵌入的 `.jps` 在别处被修改时，嵌入区自动重画。

## 新增：嵌入区的「打开谱面文件」入口

- 接管嵌入后，宿主原本那个"点开文件"的占位块不再出现，于是把入口补回**工具栏右端**：链接图标 + 谱面名，点击打开该 `.jps`；容器放不下时只留图标（悬停说明照旧）。

## 改动：显示模式改回下拉列表（并修掉嵌入里按钮被撑宽）

- 三个图标按钮改回**下拉列表**：按钮上是「模式图标 + 当前模式名 + ▾」。
- 弹层**不用原生 `<select>`**，改用 **Obsidian 自己的 Menu**：配色跟随主题、当前模式带勾选。原生 `select` 有两处顽疾，一并根除：
  1. 弹层底色由平台决定 —— 深色主题下会变成"浅底浅字"，看不清；
  2. 在某些上下文里它会被算进布局，把视图按钮撑成**两倍多宽**（真机截图确认，且只在嵌入模式复现，`.jps` 文件视图正常）。
- 另加两道保险，杜绝该按钮再被任何上下文改变宽度：`width: max-content` + `flex: 0 0 auto`。

## 改动：窄容器按宽度逐级退让（优先保住谱面文件名）

- 阈值按**工具栏自身宽度**判断（CSS `@container`），所以右侧栏、分栏里的嵌入也判断正确：
  - **≤400px**：先图标化「试听 / 排版 / 设置 / 视图」（图标含义明确、悬停有说明），四个按钮同时**等宽**（桌面 36px / 嵌入 32px）；
  - **≤250px**：最后才把「打开谱面文件」也图标化 —— 谱面名是"这份谱是什么"的唯一标识，优先保住它。
- 「试听」按钮改用 **SVG 播放/停止图标**（原先是 `▶ 试听` 纯文字，文字一藏就什么都不剩）。

## 改动：工具栏其他打磨

- **控件高度统一**：移动端 Obsidian 会给 `button` 套触控尺寸（`--touch-size-*`），而「视图」是自绘外壳、不吃那套尺寸 → 两者不等高。现在统一由 `--ijipu-ctl-h` 钉死（桌面 24 / 嵌入 21 / 移动端跟 `--touch-size-xs` 与 `--touch-size-xxs`），四个按钮与右侧链接同高。
- **设置图标改为齿轮**，形状与 iJipu 应用顶栏「页面设置」完全一致（轮环 r=3.1 + 8 根轮齿 + 中心轮毂 r=1.3），只按插件既有约定把线宽定为 1.8（轮环/轮毂）/ 1.5（轮齿），以适配深色主题下的可读性。
- **「谱面自带设置 N 项」移入设置对话框**：原先挂在工具栏上（挤占按钮位置、明细只能悬停看），现在对话框顶部列出**具体是哪几项、值是多少**，也正好解释下面控件初值的来源。

## 验证

- `tsc -noEmit` + esbuild 构建通过；`npm run smoke` **108 项断言全绿**。
- `![[檐下声.jps]]` 嵌入在**阅读模式与实时预览**下均正常显示谱面（真机实测确认；此前两版都只显示"未知嵌入块"）。
- 工具栏在**嵌入 / `.jps` 文件视图 / ```jps 代码块**三种入口下形态一致；窄宽度退让、图标态等宽、移动端控件等高均按上述阈值生效。

# 爱记谱 iJipu 0.5.0

> 本版随 `@ijipu/engine` 同步 **adj392 / adj393 / adj394**：渐强/渐弱在**默认设置下终于能显示**
> （此前只在"拍级"布局渲染，而默认是"空间优先"→ 静默不显示）、`!` 可收在 `-`/`.` 之后、
> 音符注释新增 `+`/`-` 抬升降低；并**修掉插件一个把告警当错误的老毛病**——
> 以前只要谱面有一条语法告警（多空格、孤立 `&`、无法识别的符号…）整页就变成"解析失败"，
> 现在告警**不再阻断渲染**，且在谱面下方显示，并同时给出**正确语法规则**。

## 修复：语法告警不再阻断渲染（插件此前把 warning 当致命错误）

- **现象**：同一份 `.jps` 在 iJipu 应用里能正常显示，在 Obsidian 里却整页提示「简谱解析失败」。
- **根因**：引擎 `parseJps` 的 `errors` 数组**同时装 error 与 warning**（用 `severity` 区分）；应用侧一直按 severity 分级，插件的 `renderScore`/`renderScoreFull`/`playScore` 三处却只看 `errors.length > 0` → **任何一条告警都会让谱面不渲染**。
- **修复**：新增纯逻辑 `src/parseIssues.ts`（`splitParseIssues`）按 severity 拆分——只有 `error` 阻断渲染/试听，`warning` 随渲染结果一并返回；`scorePane` 在谱面下方显示可展开的告警区 `⚠ N 条语法告警（不影响显示）`。

## 新增：告警/错误同时给出「正确语法规则」

- 引擎 `ParseError` 新增 `hint`（**正确写法 + 最小示例**），17 处报错点全部补齐；插件在错误区与告警区逐条显示 `正确写法：…`（如「引号要成对闭合，如 `1"渐强" 2`」）。

在 Obsidian 笔记中用 ` ```jps ` 代码块把 **.jps 简谱脚本**渲染为可视化简谱（SVG），并可**试听**。渲染引擎复用 `@ijipu/engine`（与 iJipu 应用一致），设置项与 iJipu 一脉传承。

## 主要功能

- **可视化简谱渲染**：引擎支持 `.jps` 描述头、Q/C 行、修饰符、连音线、多声部、小节线 / 反复 / 跳房子
- **试听**：Web Audio 合成（SynthBackend），播放色块逐音符跟进（iJipu 同款 playheadPosOf 逻辑），多声部同时高亮
- **三种显示模式**：整页 / 满宽 / **谱面**（默认，自动消除页边距、最大化有效观看面积）
- **设置项与 iJipu 应用一脉传承**：页面 / 字体 / 行距 / 渲染 四组共 30+ 项
- **frontmatter 覆盖**：单笔记可用 `ijipu_*` 键覆盖全局默认，优先级：默认 < 全局 < frontmatter
- **插件卸载 / 切笔记自动停止试听**：避免失去控制
- **赞赏入口**：设置页「支持作者 ❤」链接到 iJipu 应用微信赞赏码

## 用法

在任意笔记写 ` ```jps ` 代码块即可：

```jps
V: 1.0
B: 两只老虎
Z: 法国童谣 词曲
D: C
P: 4/4
Q: 1 2 3 1 | 1 2 3 1 | 3 4 5 - | 3 4 5 - |
C: 两只老虎 两只老虎 跑得快 跑得快
```

详细 frontmatter 键对照表见 `README.md`。
