# 爱记谱 iJipu 0.33.0

> **本版是"一版多端"版本**：插件从"仅桌面端"变成**桌面端 + 手机端都可用**
> （`manifest.json` 的 `isDesktopOnly` 由 `true` 改为 **`false`**）。
> 同时把"源码编辑"这条线补齐：手机端用**宿主自己的编辑器**打开 `.jps` 源码，配 iJipu 那套
> **语法着色 + 语法错误提示 + 行离开自动格式化**，点「看谱」即回谱面预览。
> 另外把一组"共性能力"下沉进引擎（应用与插件共用同一份实现），并修掉编辑视图里工具条
> "不显示 / 闪动 / 落位不稳"的一串问题。
> 0.32.0 → **0.33.0**（MINOR：新增手机端支持与源码编辑能力，无破坏性变更）。
> **既有谱面与 `.jps` 语法零改动**。

## 手机端也能用了（本版主题）

- **`isDesktopOnly: false`** —— 之前唯一的桌面依赖是内嵌编辑器用的本机服务（`node:http`/`node:crypto`），
  现已改为**惰性加载且只在桌面端走**；手机端不会去碰 Node 接口。
- **桌面端**：保留内嵌的完整 iJipu 编辑器（本机服务 + 页签内完整应用）。
- **手机端**：`.jps` 走宿主原生方式 —— 阅读模式显示**插件自己的谱面预览**（含试听、排版、设置）；
  点「编辑」改用**宿主编辑器**打开源码（见下），点「看谱」回到预览。
- **两边一致的部分**：` ```jps ` 代码块、SVG 渲染、试听与音源、格式化、设置项与随谱携带的 `# jps-config`。

## 源码编辑（手机端重点，桌面端同样受益）

- **语法着色用 iJipu 自己那套**（用户要求"用应用里的源码高亮方案，而不是 Markdown 的"）：
  分词规则抽到引擎（`tokenizeJpsLine`），Obsidian 侧用 CodeMirror 6 的 decoration 渲染，
  配色取自应用的两套 `--jp-hl-*` 值（深/浅主题各一套）——**不再借用 Markdown 的高亮**。
- **语法错误显示**（用户问"源码有 jps 语法错误有没有错误显示机制？"）：出错行**淡红底**、告警行**淡橙底**，
  鼠标停在出错行显示**"哪儿错了 + 正确写法"**（文案与应用的错误提示同源，都来自引擎的 `hint`）。
- **错误音符块加外框**（用户要求"重点突出错误音符块，如加红外框"）：把出错位置归到**空格分隔的那个音符块**，
  给它加红/橙单线外框（与应用编辑器的 `hl-err-block` 同一口径）。
- **格式化**：工具条上的「格式化」按钮（只在源码态出现）+ **光标离开本行时自动格式化该行**（与应用的"按应用规范"同一份 `formatLine`）。
- **按应用规范整篇格式化**：文件视图/命令面板/代码块工具条三处入口都用引擎 `formatJps`，
  并保证**幂等**（点一次改一次文件的问题已修）。
- 源码编辑页签里**中和宿主的 Markdown 着色**：`==高亮==` 的黄底、加粗/斜体/链接色都不再影响 `.jps` 源码。

## 编辑视图里的工具条（一串实测反馈的收口）

- **不显示**：根因是"每次显示都重新判定落位"这套重量级逻辑被放在了**显示之前**，
  一旦抛错或踩到已被宿主编辑器重建的旧元素，显示那一步就永远不执行 ⇒ 改为**先显示、再落位**，
  且落位判定全程 `try/catch`、一律用**现查的活元素**（异常会写进设置页诊断，但绝不影响可见性）。
- **闪动**：同一个原因的另一面 —— 判定结果在"块外/块内"之间来回翻；现在**每个面板只判定一次落位**
  （先试块外，不行才贴回块内），鼠标移动只做"保持显示"这件轻量事。
- **抓不住**：鼠标移到工具条上时不再收起（含 240ms 延迟复查），事件改挂容器 ⇒ 元素被重建后依然有效。
- 桌面上工具条的规范位置是**谱面块外侧左上角**（阅读视图与编辑视图一致）。

## 引擎同步（共性能力下沉，引擎包 0.32.0 → 0.33.0）

用户要求"共性的功能都可以独立到引擎层面、应用端也应同样处理"。本版把 **8 组**两端各写一遍的纯逻辑收进引擎，
插件与应用**消费同一份实现**（插件的 `vendor/engine` 与应用引擎**逐文件哈希一致**，且已加机器闸门）：

| 能力 | 引擎模块 | 顺带修掉的口径漂移 |
|---|---|---|
| 试听色块的分组/定位/配色 | `playback/playhead` | 单声部色块下界两端不同（同一份谱两端**高度不一样**）——统一为含下沿 0.5 字号延伸 |
| 解析问题的分级/排序/计数/展示行 | `diagnostics/problems` | 提示措辞两端不同——统一为 `错误[第3行 第5列] 消息`（带分级标签） |
| 音源库清单与取用顺序 | `playback/soundbanks` | 顺序按**层级**定序（宿主直供 → 用户文件 → 缓存 → 内置 → 下载），两个宿主各自映射 ⇒ 行为都不变 |
| 整篇/逐行高亮模型 | `highlight/model` | 两端不再各自"按行取 token + 查错误块 + 判级别" |
| 高亮与问题提示配色 | `highlight/palette` | 插件 CSS 与应用 `theme.css` 由断言绑定，改配色不会再漏掉一端 |
| 试听时钟 | `playback/clock` | 推进/暂停续播/取消/到点一次的语义只有一份 |
| 新建空白谱模板 | `samples/template` | 应用那支 `.jps` 文件与插件常量被断言钉住 |
| 设置分层判定规则 | `settings/layers` | 值等价 / 是否等于默认 / 改动键 —— 避免"多写一条 `# jps-config`" |

- **嵌入版 iJipu 升到 v0.51.0**（含引擎 0.33.0）—— 按"先升应用版本 → 再生成嵌入产物"的顺序重新生成
  （`adj733` 闸门断言嵌入版版本 == 应用 `APP_VERSION`）。

## 其他修复

- **`.jps` 文件在阅读模式下会自动回到谱面预览**（此前会停在源码态）。
- **文件视图与代码块工具条的按钮**统一：「编辑」（源码态显示「看谱」）+「格式化」（仅源码态），
  不再出现"图标与排版重复""源码态却看不到格式化"这类问题。
- 手机端源码编辑框高度不再被工具条压掉一半（工具条只保留必要按钮）。
