# 爱记谱 iJipu 0.36.1

> **本版是说明与开关改进版**（PATCH）：把设置里那个容易误解的「**开发者**：允许嵌入版调用插件能力」
> 改名为「**嵌入版通道（导出图片 / MIDI 需要）**」、说明写清它管着哪两条通道；并把该开关从
> "**重开 Obsidian 就自动关闭**"改为"**记住**"；另外按最新口径把**导出范围默认改成「跟随视图」**、
> 手机上把「复制为图片」换成「**保存图片到谱面同目录**」。0.36.0 → **0.36.1**。
> **既有谱面与 `.jps` 语法零改动**。

## 改：导出范围**默认改为「跟随视图」**（`adj873`）

`⋯ 更多 → 导出范围`（与设置页那一项是**同一个值**）的**默认值**从「页面」改成「**跟随视图**」：

- **跟随视图**（新的默认）：按你当前看到的来 —— 显示「谱面」就按墨迹包围盒导出/复制，
  显示「整页 / 满宽」就按整页 + 留白；
- 「页面」（整页 + 留白）与「谱面」（墨迹 + 每边 2px）照旧可选，菜单与设置页里**当前项打勾**，
  一眼能看出正在按哪种口径，也能就地改回去。

为什么改：原来刻意默认「页面」，是怕老用户升级后导出尺寸**静默变化**；你现在明确要"默认跟随视图"
（`2026-10-11`）—— 导出/复制与自己看到的一致更符合直觉。**在「谱面」模式下导出会比以前更小**
（少了整页留白），这是这次改动唯一需要留意的变化，改回「页面」即可恢复旧行为。

## 改：手机上「复制为图片」→「**保存图片到谱面同目录**」（`adj873`）

**问题**：`⋯ 更多 → 图片出口（1× / 2× / 4×）`在手机上**做不到** —— 手机宿主的 WebView 没有
写剪贴板图片的能力，点了只会得到一句报错。

**现在**：

- **手机**：这三项变成「**保存图片（2×，默认）**」「保存图片（1×）」「保存图片（4×）」，
  图片直接**存进这份谱所在的目录**，文件名 `<谱名>.png`
  （`.jps` 文件视图 / 嵌入 ⇒ 该文件同目录；```jps 代码块 ⇒ **当前笔记同目录**；取不到 ⇒ 库根）；
  **重名会自动加 `-2`、`-3`…，绝不覆盖已有图片** ✗；存完的提示里写明**完整的库内路径**；
  多页谱**只保存第 1 页**并如实说明（另一半请用「导出 PNG」命令）。
- **桌面**：**一切照旧**（仍是复制到剪贴板：2× = 144 DPI、4× = 288 DPI）。
- 图片的**取图路径与画质口径两端完全一样**（都在嵌入版应用里渲染，再补 pHYs 的 DPI 信息）
  ⇒ 手机上存下来的图与桌面上贴出去的是同一张。
- 菜单动作 id 不变（`copy-image-1/2/4`）⇒ 只是"落点"按平台分流，别处的路由与设置都不用动。

## 改：设置项改名 + 说明写清两条通道（原来会误导）

**问题**（你问「开发者选项的意义何在？」时我查代码发现）：这个开关其实是
「**嵌入版 iJipu（应用）↔ 插件**」**两条** postMessage 通道的**总开关**，而你平时点的
「导出 PNG / 导出 MIDI / 复制为图片」走的正是其中的 **插件 → 应用** 那一条 ——
可旧名字叫「开发者…」、旧说明只写了 **应用 → 插件** 那一半（而那一半应用侧**目前没有任何调用方**）
⇒ 用户会以为"这跟我无关"，真去导出图片失败时也找不到原因。

**现在**（设置 → iJipu → 嵌入版）：

- 名字改为「**嵌入版通道（导出图片 / MIDI 需要）**」；
- 说明里分开写清：
  · **插件 → 应用**：**导出 PNG / 导出 MIDI / 复制为图片**（渲染要用应用里的画布、合成要用音色库）；
  · **应用 → 插件**：能力探测与渲染（**目前仅供开发与将来使用**，日常用不到）；
- 并写明：默认关闭是**安全优先**（这条通道能让页面里的代码驱动插件），打开后仍只认
  **本插件自己打开的嵌入版窗口**，且方法在白名单内、参数逐项校验；
- 关掉它**不影响**「导出 SVG / 复制 SVG 文本」（那两条走插件自己的引擎，不经过这条通道）。

## 改：开关**会记住**了（不再每次重启都要点一次）

原来它是"仅本会话有效"的内存开关：重开 Obsidian 后想导出图片，得先去设置里重新打开一次。
现在存进插件设置（`data.json`）⇒ **打开一次即长期有效**。

- 属性仍是 `L1 界面偏好`（与具体谱无关、不随谱走），已登记到应用仓库 `docs/SETTINGS-AUDIT.md`；
- 关闭时的报错文案也跟着改了（原来指向"开发者"，现在指向新的设置名，按提示就能找到那一行）。
