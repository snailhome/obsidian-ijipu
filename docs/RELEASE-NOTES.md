# 爱记谱 iJipu 0.28.1

> 随 `@ijipu/engine` **0.30.1** 同步：**修"含 `{dsb}`/`{bz}` 时播放色块顺序乱"**。
> 0.28.0 → **0.28.1**（PATCH：引擎单处缺陷修复，插件自身代码与设置不变）。

**修复：临时多声部/伴奏段存在时，播放色块会来回跳**

- **现象**：谱面里有 `{dsb}`（临时多声部）或 `{bz}`（临时伴奏）时，播放中的**色块位置会来回跳**，
  看起来像"演奏顺序乱了"；**实际发声顺序是对的**（音频排程按每个事件的时间点走），
  错的是给色块用的那份**事件数组**。
- **根因**：段层事件（段内容那些音）是在**跑到主旋律音符时才补发**的，且被整段排在数组**最前面**，
  于是数组里的时间戳不再是递增的（形如 `0, 2s, 0, 2s, 4s…`）。而色块定位用的是**二分查找**
  "最后一个不晚于当前时刻的段"——它**默认数组已按时间排好**（代码注释里也这么写着），
  前提被破坏后，二分就落到错误的段上 ⇒ 色块来回跳。
- **修法**：生成播放序列时，返回前把事件按时间**稳定排序**（同一时刻仍保持"段内容在主旋律之前"，
  因此点击某音起播的行为不变）。
- **验证**：对"`{dsb}` + 反复"、"`{bz}` + D.C."、"`{dsb}` + 重叠房子 + `:|&ds`"三种写法
  断言事件时间**单调不减**（并已确认"不排序时断言会失败"）；引擎与应用冒烟测试全部通过。

# 爱记谱 iJipu 0.28.0

> 随 `@ijipu/engine` **0.30.0** 同步：**连音线纵向定高口径收敛**（各按自己区间）、
> **修饰符让位查表**、**`&ty`（大跳跃）位置再上移 2px**。
> 0.27.0 → **0.28.0**（MINOR：引擎带来多项用户可感知的排版变化，插件自身代码与设置不变）。

**一、连音线高度：不再"整行统一"，改为各按自己范围内的修饰符定高**

- **旧口径的问题**：连音线的让位高度取的是**整行**的最大值（高八度点个数、上方修饰符个数），
  于是行内**任一**音符带高八度点或波音，**全行每条线**都被抬高——实测多抬 **3.6~8.7px**，
  表现为"有些连音线离音符太远"。另外，层次判据要求按**墨迹**留间距，而线条只按**弦** `y` 计算、
  没扣弧线的**垂度**（弧顶 = `y − 垂度/2`），跨度越长弧顶越往上顶，弧顶到数字的间距从 4.2px
  涨到 **12.7px**。
- **新口径**（你的口径："**都就自己范围内的修饰符来定连音线高度，不要求整行的连音线水平对齐**"）：
  每条线**只统计自己覆盖的那段音符**（高八度点、上方修饰符都在自己区间内取），
  锚点也取**本线区间内最低**的音符（"各线按自己区间定位、能低就低"）；
  同一行里两条线**不再互相拖累**——例如 `Q: 1'/ 7// (3// 3/) 5/ (6 1'/ (5'/ | 5')` 里，
  前一条贴着自己的音符（`y=142.2`），后一条因区间含 `5'/ 1'` 才抬高（`y=138.6`）。
- **跨行连音线的两半**同样按自己区间定高（此前用的是行级最大值）。

**二、修饰符"让位量"改为按符号查表（不再一刀切）**

之前"连音线为上方修饰符让开多少"用的是**一个统一的常量**，而各类记号的墨迹高度差别很大
（波音的图形墨迹只有约 `3.3×s`，文字类颤音按字身比是 `7.2×s`，上滑音接近 `8.2×s`）
⇒ 一个常量必然"有的太松、有的压住"。现在**按符号取真实墨迹高**再叠层间距：
波音让得少、滑音让得多，**各按自己的字形**。表值与图形数据同源，并有断言防止两者失配。

**三、波音（`&sby` 类）与连音线的避让口径更正**

按你给的例子 `(1/ (1&sby)- | 1)` 与说明——「波音与连音线明显会重叠……这里的**前后连音都应该抬高**，
**类型有高八度点或其它修饰符一样**」——恢复"**所有上方修饰符都让位**"
（此前我误按"波音在连音线下方"把它排除在外，导致两者相交）。

**四、`{dsb}` 段内连音线不再重复绘制**

同一段 `( … )` 曾被两条路径各画一份：段层那份位置正确，主旋律那份按行基线定位、
又被包络下移量再推一次 ⇒ **压在段层音符上**。现在只保留段层那一份。

**五、`&ty`（大跳跃）再上移 2px**

记号高度维持 **1.25 倍**（宽度不变），与小节线墨迹上端的间距由 `0.5px` 调整为 **`2.5px`**
（即再往上 2px）。该间距此前是用**真实像素扫描**标定的，不再靠估算。

**六、其它修复**

- 点 `{dsb}` 下声部（主声部）起播时，上声部事件不再被整段切掉（此前只演奏单声部）。
- 预览区**单击**音符只定位光标，不再从该音符播放；播放改由**双击** / `Ctrl+单击`触发。

# 爱记谱 iJipu 0.27.0

> 随 `@ijipu/engine` **0.29.0** 同步：**`{dsb}` 主副声部对换**、**色块三连修**、**试听单实例**。
> 0.26.0 → **0.27.0**（MINOR：引擎带来多项用户可感知的排版/演奏/试听变化，插件自身写法与设置不变）。

**一、`{dsb}` 临时多声部：主副声部对换（演奏音色与色块随之对调）**

- **归属翻转**：`{dsb … }` **里面**的音符是**副声部**，**外面**的主旋律才是**主声部**
  （此前相反）。这样与临时伴奏 `{bz}` 的读法一致：写在 `{}` 里的是"附加声部"。
- **显示效果完全不变**：段内容仍在上排、两层仍与单声部居中对齐（实测坐标与翻转前一致）。
- **演奏与色块对调**：段内容 → 第二音色 + 力度 `0.75` + 副色块；
  **包络外的主旋律 → 主音色 + 力度 1 + 与单声部同色的色块**
  （你之前说的"下面声部的演奏音色、色块随单声部"）。

**二、播放色块：三处修复（这一段此前"像没有色块"）**

- **色块宽度曾变成 0 ⇒ 整段画不出来**：段层右界钳制取的是"同组**所有段右界的最小值**"，
  本意"别越出任何一段"，实际成了"别越出**最窄**那段"。同一行有多段 `{dsb}` 且右界差别很大时
  （实测 `151.5 / 303.5 / 530.1`），后两段的主旋律色块被压成 **0 宽**、完全不可见。
  现改为按**本音符所属那一段**取边界。
- **色块不再依赖音源**：此前"先取音源、加载成功才建播放序列"，音源任一环节失败
  （缓存 / 内置音源 / 联网下载）就会连**色块与播放位置高亮**一起没有，看起来像"点了播放没反应"。
  现在**先建序列与色块、再取音源**；音源失败只降级为**无声**，并明确提示"色块与播放位置照常显示"。
- **上下两块不再错位**：色块的上下分界此前由"行基点"反推，实测偏 **3.3px**、
  两块之间露出约 **7px 的缝**；现改用**两排的真实基线**计算 ⇒ 两块**严格相接且等高**。
  顺带修掉"段内容区间之外的主旋律音拿不到定界"的漏块。

**三、试听：`Ctrl+鼠标左键` 点音符 + 进度读数**

- **`Ctrl + 鼠标左键` 点预览区音符** ⇒ **打开试听并从该音符开始播放**；
  **已经开着就保持**（不另起播放进程），**没开就打开**。
  同一份谱子**只会有一个试听态**（此前可能同时跑两路）。
- **试听对话框新增 `mm:ss / mm:ss` 进度读数**（已播 / 总长），与色块、高亮**同一时间轴**。

**四、其余修复**

- **导出的 MIDI 分轨**（`adj719`）：`{dsb}` 的上下两层**共用同一个声部号**，
  而分轨只按声部号 ⇒ 两层被塞进同一条轨、后一个音色覆盖前一个，
  导出的 MIDI 听起来"只有一个声部"。分组键补上**声部角色**后，两层各占一条轨。
- **色块右缘**不再把"布置网格的间隙"算进去（`5/` 与后一个音之间空 9.7px 时，
  色块会盖到后一个音符上）。
- **色块定界**按"本音符所属那一段"取（同一行多段 `{dsb}` 时不再串段）。

**五、取证手段（给以后排查用）**

- 播放时在控制台输入 **`__ijipuPlayhead()`**，可打印：轨道段数、当前时刻、
  本页各组的可见性与坐标、以及 DOM 里色块元素的实况。
  这类"只在你的环境复现"的问题，下次一句话就能定位。
