## 为什么是 PATCH 而不是 MINOR

插件仓库本轮**自身代码零改动**（改动只有：同步过来的 `vendor/engine` 2 个文件、重新生成的
`src/gen/webappAssets.ts` 嵌入产物、版本号与说明文档）。按 SemVer 的"内部依赖更新"走 **PATCH**
（先例：`0.41.1`～`0.41.7`）。

## 引擎：`0.38.4 → 0.38.5`（倚音三处几何，用户口径）

1. **倚音字号**：`0.5` → **`2/3` × 主音符**。13 号时 6.50 → **8.667**；18 号时 9.00 → **12.00**。
   字号变了，槽宽与组内间距按比例自动跟着变（`0.62×字号` / 多倚音 `0.5×字号`）。
2. **第一条减时线**：原来"与主音符数字上沿同高"，改为 **主音符墨迹高的 2/3 处**（`基线 − 0.8×字号×2/3`）。
   13 号 143.9 → **147.40**；18 号 → **150.20**。
   ⚠ 连带：**倚音数字基线跟着减时线走**（否则线会横穿数字墨迹）。
3. **减时线相邻两条间距**：`1.2×s` → **`1.5×s`**。13 号 0.867 → **1.083px**；18 号 **1.5px**。
   低八度点与连接弧线起点都按"最后一条线底"算 ⇒ 自动跟随。
4. **防误伤**：**方框小节序号**原先借倚音的字号比例，已拆出独立常量 `BAR_NUMBER_SIZE_RATIO = 0.5` ——
   **序号的字号与外观没有变**。

`vendor/engine` 按逐文件 SHA256 双向对比同步：同步前差异 **2 处**（`layout/spacing.ts`、`render/index.ts`），
同步后**差异 0、插件侧多余 0**（闸门 `adj770` 绿）。

## 更新：内嵌的 iJipu 应用 `0.67.1 → 0.67.2`

按项目的**顺序铁律**（`E-2026-374`）：先在应用仓库提交并打 tag（`v0.67.2`：`f746a28`）、推送，
**再** `npm run build:embed` + `node scripts/embed-emit.mjs` 重生成嵌入产物。
跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）**通过**（产物里 `appVersion: "0.67.2"`）。

嵌入版这一版带来的东西：

1. **倚音排版**（上面三处）—— 库内 `.jps` 的预览与嵌入版都跟着变。
2. **"为什么读不到图"会说清楚了**（`adj979`）：谱和背景图放在**桌面 / 文档 / 下载**里时，
   浏览器（Chromium）不允许网页授权这三个目录 ⇒ 应用现在会在确认条上直接把原因说出来，
   并给一条出路（「改用工作区」）。⚠ 插件这一侧**看不到这条提示**：嵌入版跑在跨源 iframe 里、
   也不能弹文件夹选择器，库内文件本来就由宿主（vault）提供基准，不受这个限制。
