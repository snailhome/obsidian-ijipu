# 爱记谱 iJipu 0.33.2

> **只修一件事：让"同一提交 ⇒ 逐字节相同的产物"在 CI 上也成立**（PATCH）。
> `0.33.1` 已把构建戳改成 UTC、并移除了 lookbehind（审核那条 Error）；发布后我拿 **CI 产物**与
> 本地重建比对，发现**仍差 1 分钟** —— 根因是 CI 的 `actions/checkout` 是**打包克隆**，
> 构建脚本读不到松散 git 对象时会**回退成"构建那一刻"**。本版让提交时间有两条**同值**来源，
> 两条都失败也只写"未知日期"，**绝不回退当前时间**。
> **既有谱面、`.jps` 语法、界面行为零改动**。

## 修了什么

- **构建时间取"提交时间"，并在 CI 侧兜底**（应用与插件两侧的 `scripts/gen-build-info.mjs`）：
  - 先按老办法读 `.git/objects/xx/yyyy`（松散对象，本地 clone 常见）；
  - 读不到（CI 打包克隆）时改用 `git log -1 --format=%ct <sha>` —— **同一个提交时间**；
  - 两条都失败才写"未知日期"（确定性优先）。
- **验证方式升级**：不再只看"本地再构建一次是否一致"，而是**拿 Release 里的 CI 产物逐字节比对**
  （本地重建只能证明"同环境稳定"，证明不了跨环境一致 —— 这正是上一版漏掉的那半）。

## 为什么值得单独发一版

审核的 Build verification 检查的就是"**审核方自己重建的产物**与 **Release 附件**是否一致"。
只要产物里含任何一个"构建环境相关"的值，这条就永远过不了。本版之后：

- 产物里与时间有关的值只有**提交时间**（由 git 决定，任何机器任何时区都一样）；
- 时区按 UTC 格式化；取不到时间时不写时间。

## 同版同步

- 嵌入版 iJipu 升到 **v0.51.2**；引擎包 `0.33.1 → 0.33.2`（引擎源码无逻辑变化，同批文档与脚本）；
- 插件 `vendor/engine` 与应用引擎仍**逐文件哈希一致**（有闸门）。

## 验证门

- `npx tsc -noEmit -skipLibCheck` 0 错；`npm run smoke` **340 passed, 0 failed**；`npm run build` 正常；
- `node scripts/release-body.mjs` 命中当版 `# 爱记谱 iJipu 0.33.2`；
- 发布后**实测**：CI 产物与本地重建**逐字节一致**（这条是审核那项检查的判据）。
