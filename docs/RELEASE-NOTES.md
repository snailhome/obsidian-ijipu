# 爱记谱 iJipu 0.15.0

> 本版只做一件事：**同步 `@ijipu/engine`（0.16.1 → 0.17.0）**——带来**多声部组之间的小节线对齐**，
> 以及设置写盘口径的两处修正。插件自身代码无功能改动。
> 0.14.1 → **0.15.0**（MINOR：插件里能直接看到排版变好，不只是修 bug）。

## 新增（来自引擎）

- **多声部块之间的小节线对齐**（`adj601`，用户口径）："第二组多声部，当自然对齐时，应尽量与上一组的小节线对齐，
  除非第二组的小节宽度比上一级对应小节宽。"
  - 此前每一组多声部块各排各的（"自然宽 / 撑满"完全独立），第二组的小节线往往落在别处，两组看起来对不齐；
  - 现在排版会记住**上一组多声部块每小节的内容宽**，下一组以此为**下限**排布（换页清空；中间只夹单声部行时不清），
    与上一组的内侧小节线对齐时补回半个小节线笔画宽的偏移；
  - 例外照旧：某小节**自然就更宽**时不压缩它（该组对应小节照自己的宽度走）；
    整组放不下时**整体放弃对齐**（宁可不对齐，也不越界或压缩内容）。

## 修复（来自引擎）

- **可选布尔设置的"关"与"没写"统一**（`adj606`）：`showInstrument`（乐器名显示）/`lyricShrink`（歌词压缩）
  这类**可选字段**的默认值是"未设置"，此前取消勾选会写进一个显式的 `false`，于是"与默认不同"永远成立。
  现在取消勾选 = 回到未设置；老笔记里已经写进去的 `"showInstrument":false` 也会在下一次保存时被清掉
  （识别口径一并把布尔的 `false` 与"未设置"视为同一状态，`0`/`''` 这类值不受影响）。
- **设置项的"是否与默认不同"判据统一**（`adj605`）：引擎新增 `nonDefaultConfigKeys`，
  与「保存设置」的**差量写出**用同一份判据——应用侧因此能在标签后标出红 `*`（插件侧不需要这个标记，但共用同一口径）。

## 验证

- `tsc -noEmit -skipLibCheck`：退出码 0
- `npm run smoke`：**160 passed, 0 failed**（引擎换新后无断言需要调整）
- `vendor/engine` 与应用 `packages/ijipu-engine/src/engine` **逐文件 SHA256 一致**（35/35 文件，差异 0）
- 引擎侧新增断言：`adj601` 跨块小节线对齐 6 条、`adj605` 非默认标记 10 条、`adj606` 可选布尔字段 5 条；
  应用侧真机实测：两组多声部的小节线坐标由 `[115.9, 161.7]` 变为 **`[176.5, 299.8]`**（与第一组同列）

## 升级

- 含**多组多声部**的谱子会看到更整齐的版面：第二组开始，各小节线与上一组对齐（除非那一小节本来就更宽）。
- 笔记里的 `# jps-config` 若曾留下 `"showInstrument":false` / `"lyricShrink":false` 这类噪音，
  下次在应用里保存设置时会被清掉；插件本身不改写源码。

## 变更

- 无破坏性变更：本轮只同步引擎的排版与写盘口径修正。
