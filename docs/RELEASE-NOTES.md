## 为什么是 PATCH 而不是 MINOR

插件仓库本轮**自身代码零改动**（改动只有三类：同步过来的 `vendor/engine/**` 4 个文件、按顺序铁律
重新生成的 `src/gen/webappAssets.ts` 嵌入产物、版本号与说明文档）。按 SemVer 的"Bug 修复 + 内部依赖更新"
走 **PATCH**（先例：`0.35.1`、`0.41.1`、`0.41.2`、`0.41.3`、`0.41.4`、`0.41.5`）。

## 引擎：`0.38.3 → 0.38.4`（连音线配对收成唯一实现 + "没画出来"改成告警）

用户实报「`Q: (4/ 6/ | (2'- 2'/) 1'/ (y7/ 6/ 3/) | 5)` 这一段里，内层的 1 个连音线和 1 个等时值连音线
都没有画出来」——查下来根因是**上一行多了一个 `(`**：它让嵌套整体深了一层，而引擎有条"**最多两层嵌套**"
的渲染上限，更深的配对会被**静默丢掉**（三处全静默：层数上限 / 谱末悬空的 `(` / 多出来的 `)`）。

本轮把这三处**全部改成告警**（指出是**哪一个 `(`**、带"正确写法"），并把**连音线配对**从布局里抽成
**唯一一份**纯函数 `parser/slurPairs.ts`（`parseJps()` 调一次：`pairs` 给布局算几何、`problems` 并进
`parseResult.errors`）。⇒ 插件这边的好处是**自动的**：插件的解析问题提示、库内 `.jps` 的问题条读的就是
`parseResult.errors`，所以**那三条新告警在插件里也能看到**，不需要插件改任何代码（`vendor/engine` 同步即得）。

同步前差异 4 处（`types.ts` / `layout/index.ts` / `parser/parser.ts` / 新增 `parser/slurPairs.ts`），
同步后**差异 0、插件侧多余 0**（闸门 `adj770` 绿）。

## 更新：内嵌的 iJipu 应用 `0.66.0 → 0.67.0`

按项目的**顺序铁律**（`E-2026-374`）：先在应用仓库提交并打 tag（`v0.67.0`：`db3ffd7`）、推送，
**再** `npm run build:embed` + `node scripts/embed-emit.mjs` 重生成嵌入产物。
跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）**通过**（产物里 `appVersion: "0.67.0"`）。

嵌入版这一版带来的东西：

1. **连音线"没画出来"会告诉你**（`adj973`）：问题条里会出现「这条连音线嵌套超过两层（最多两层），没有绘制」
   「连音线的 `(` 没有对应的 `)`」「多了一个 `)`」三类提示，**行列锚点正点在那个括号上**。
   这解决的是"谱面少了两条线、却一句提示都没有"的老问题（用户本轮就是靠肉眼找那个多出来的括号）。
2. **输入条默认开关**（`adj974`）：PC ⇒ 默认关、手机 ⇒ 默认开（旧口径把"窗口 ≤1024px"也算进
   "该默认打开"，于是插件在**窄侧栏**里打开时会默认弹出输入条 —— 现在不会了）。
   ⚠ 只影响没手动开/关过的情形；用户存过的偏好不被覆盖。
3. **「保存到工作区」对话框**（`adj972`）：目录多时改为**列表内滚动**，不再整个对话框滚
   （此前"取消 / 保存"会被目录列表顶到屏幕外）。
