## 引擎：`0.38.5 → 0.38.6`（连音线三处修复）

1. **替谱段的附点贴紧数字**（`adj982`）：段层（`{tp}`/`{bz}`/`{dsb}`）原先给附点取 x 用的是"拍位栅格"
   或"格内余白三等分"，格子一宽就把附点推到数字很远、甚至贴上 `&ykh` 的右括号。改为与主旋律同一口径
   `DOT_AFTER_DIGIT_GAP`：附点紧贴数字右缘；且**只挪附点、不动数字的 x**（段层与主旋律的同拍左缘对齐不变）。
2. **反复跳回的连音线终于画出来**（`adj983`/`adj983b`）：末行 `(6/[5/]` 之后是 `:|`、`|:` 之后紧跟
   `6/)`，那个 `)` 就是它的闭合。以前线性配对把 `)` 判"多余"、把 `(` 判"没闭合"，布局也画不出
   "末行 → 首行"倒着的跨行线。现在：`|:` 之后的第一个 `)` 记成跳回闭合候选（也允许它同时闭合
   反复之前那条 `(` —— 真谱里两处 `(6/[5/]` 共用同一个 `)`），谱末配成 `wrap` 对，
   末行画到行末、首行从左边距接到该音。
3. **"嵌套层数"改按实际包含关系算**（`adj984`）：原先深度取"打开那一刻栈里还有几个 `(`"，
   而"等跳回闭合"的那条 `(` 会一直挂在栈上 ⇒ **后面每条括号的深度被顶高一层**，两层的正确写法
   被算成三层、被"最多两层"判据丢掉并告警。改后按包含关系算（接续类 `houseTie`/`wrap` 与
   `(3)` 这种"上一段结束、下一段开始"的连接点不参与计数）。

`vendor/engine` 按逐文件 SHA256 双向对比同步：同步前差异 **3 处**（`types.ts`、`layout/index.ts`、
`parser/slurPairs.ts`），同步后**差异 0、插件侧多余 0**（闸门 `adj770` 绿）。
