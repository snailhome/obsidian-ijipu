# 爱记谱 iJipu 0.14.1

> 本版只做一件事：**同步 `@ijipu/engine`（0.16.0 → 0.16.1）**——按用户口径收紧「未封闭房子」的演奏范围。
> 插件自身代码无功能改动。0.14.0 → **0.14.1**（PATCH）。

## 同步的引擎修复

- **未封闭房子 `|["n." … |]/` 的范围**（`adj598`，用户口径）："更严格的说法是演奏到下一个 `:|` 或 `&ds`
  或 `&dc` 或 `&fine` 或 `||`，即演奏到**下一个跳跃或结束**"。
  - 此前只按**线型**判断（`:|` / `:|:` / `||` / `||/`），**不看小节线修饰符** ⇒ 房子后面若先出现
    `|&ds` / `|&dc` / `|&fine`，它们不算"跳跃或结束"，房子会一路吞到更远的 `:|`——
    把本不该跳的音乐也吞进"第 1 遍房子"，其它遍就整段不奏。
  - 而且"跳过房子后落到的那根线"上，**它自己的 `&fine`/`&ds`/`&dc` 被直接跳过**（`|&fine` 形同没写）。
  - 现在：判据 = **反复线 `:|`/`:|:` + 结束线 `||`/`||/` + 带 `&ds`/`&dc`/`&fine` 的小节线**；
    落到那根线时**只抑制它的 `:|` 回跳**（该反复已在跳过房子时越过），
    它自己的"跳跃 / 结束"照常生效。

## 验证

- `npm run smoke`：**160 passed, 0 failed**（引擎换新后无断言需要调整）
- `vendor/engine` 与应用 `packages/ijipu-engine/src/engine` **逐文件 SHA256 一致**
- 引擎侧新增 4 条断言（`[127]`），且既有跳房子 / `&ds` / `&dc` / `&fine` 断言（adj126、adj295、adj359
  的三房子用例）**全绿** ⇒ 已封闭房子 `|]` 与既有跳跃语义未受影响

## 升级

含 `|["1." … |]/` 这类**未封闭房子**的谱子，试听时的反复范围现在与谱面一致：
房子一直奏到下一处跳跃或结束（`:|` / `&ds` / `&dc` / `&fine` / `||`），之后照常继续。

## 变更

- 无破坏性变更：本轮只同步引擎的一处演奏范围修正。
