# 爱记谱 iJipu 0.7.3

> 本版随 `@ijipu/engine` 同步 **adj411**：修**附点音符的减时线在附点前断掉**——
> `1//2/.` 这类附点写在一拍后半的谱子，`2` 的减时线原来止于数字右缘就断了，
> 而附点是画在数字右侧的，看起来像"线少了一截"。现在带附点的音符，减时线会**延伸到附点之下**。
> 插件侧不需要改代码，只是引擎换新版。

## 修复：附点音符的减时线延伸到附点之下（adj411）

- **现象**：`1//2/.`（`2` 带附点）里 `2` 的减时线只画到数字右缘，附点下方是空的，水平方向"看起来断了一截"；同一小节里写成 `1//2/`（无附点）反而正常。
- **根因**：减时线（`computeBeams`）的右端一直是常量「末个音符的数字右缘」，与附点无关；而附点画在**数字右侧**（占该音符时值宽度的后半），于是带附点的音符天然"线比音符短"。
- **修复**：组尾音符带附点时，线尾取 `max(数字右缘, 末附点右缘)`。附点的圆心与右缘几何同时抽成 `dotCenterXOf` / `dotRightEdgeOf`，**与附点绘制共用同一份**，避免"渲染一套偏移、别处再算一套"的漂移（这类教训本项目已吃过：E-2026-129）。
- **不受影响**：不带附点的音符仍止于数字右缘（不误伸）；附点写在拍首时（`2/. 1//`）附点本就在线内，无多余变化。

## 验证

- 引擎 `npm run smoke` 新增 **5 条 adj411 断言**（**空间优先与时值优先两种布局各验一遍**）：带附点的减时线越过数字右缘、右端等于末附点右缘、以及"无附点不误伸"的反例；失败项 17 == 改动前基线。
- 截图目视核对四个用例：`1//2/. 3 4`（两种布局，线均延伸到附点下）、`1//2/ 3 4`（对照，不误伸）、`2/. 1// 3 4`（附点在拍首，无多余变化）。
- 插件侧 `tsc -noEmit -skipLibCheck` 通过；`vendor/engine` 与 `ijipu` 引擎逐文件哈希一致（29 个文件 0 处不一致）。
