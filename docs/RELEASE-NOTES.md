## 为什么是 PATCH 而不是 MINOR

插件仓库本轮**自身代码零改动**（改动只有：同步过来的 `vendor/engine/layout/index.ts`、重新生成的
`src/gen/webappAssets.ts` 嵌入产物、以及版本号/说明文档）。按 SemVer 的"Bug 修复 + 内部依赖更新"走 **PATCH**
（先例：`0.35.1`、`0.41.1`、`0.41.2`、`0.41.3` 都是 PATCH）。

## 引擎：`0.38.1 → 0.38.2`（同步过来的一处排版修复）

应用侧引擎改了 `layout/index.ts`（**小节序号的落点**，用户 2026-10-17 两条口径）：
① **轮到序号的那一小节若正好在行首**，序号方块从"行首隐藏小节线位置（其上没有线）"挪到
**上一行行末的小节线**下方（两处是同一条小节边界，行末那侧**有线可依**）；跨页也挪；只有**全曲第 1 小节**
（没有上一行）才留在边距线；碎片行结束时不清空行末线（它的行尾在小节中间）⇒ 再下一行自动退回行首。
② **最后一条小节线之后没有小节就不画**：源码末尾多写一个小节线（`… 4 5 6 7 | |`）会解析出一个空 seg
（"幽灵末小节"）被编号 ⇒ 现在这种"末尾空段"不编号、不画框；夹在**中间**的空小节照旧编号。

`vendor/engine` 按**逐文件 SHA256 双向对比**同步（同步前差异 1 处 = `layout/index.ts`，同步后**差异 0、
插件侧多余 0**，闸门 `adj770` 绿）。

## 更新：内嵌的 iJipu 应用 `0.64.0 → 0.65.0`

按项目的**顺序铁律**（`E-2026-374`）生成：先在应用仓库提交并打 tag（`v0.65.0`：`656b2f5`）、推送，
**再** `npm run build:embed` + `node scripts/embed-emit.mjs` 重生成嵌入产物。
跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）**通过**（产物里 `appVersion: "0.65.0"`）。

嵌入版这一版带来的东西（应用侧口径见 `docs/FILE-MODEL.md` / `USER-GUIDE.md` §八）：

1. **把 `.jps` 从文件管理器拖进窗口就能打开**（`adj968`）：桌面端走 Tauri 原生拖放（拿到真实路径 ⇒ 能写回原文件）；
   网页 / PWA 走 HTML5 拖放 + 可写句柄（Chromium）；一次拖多个只打开第一个；当前文档有未保存改动会先问一句。
   ⚠ **插件自己的嵌入版不参与拖放**（跨源 iframe 里拿不到路径与可写句柄，用户已拍板本轮不做）——
   在 Obsidian 里把 `.jps` 拖进嵌入版**仍然不会被打开**，请照旧用文库面板打开。
2. **差异框修复**（`adj967c`）：块操作条不再顶掉"改动那一行"。
3. **小节序号落点**（`adj967`）：见上面"引擎"一节。
