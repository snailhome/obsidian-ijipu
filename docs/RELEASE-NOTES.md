# 爱记谱 iJipu 0.4.1

> 本版是 0.4.0 的**修复版**（0.4.0 → 0.4.1）：修掉 `![[檐下声.jps]]` 这类嵌入**完全不渲染**（被 Obsidian 的
> 未知附件占位块覆盖并替换掉）的问题，并修掉**深色主题下工具栏/设置图标变成白方块**（谱面"纸张"样式
> 误命中图标 svg）的问题。**0.4.0 的 Release 附件（`main.js`）不含这两处修复**，装 0.4.0 的用户请升级到本版。

## 修复：`![[xxx.jps]]` 嵌入不显示谱面（被 Obsidian 占位块覆盖）

- **现象**：笔记里写 `![[檐下声.jps]]`，显示的是"无法嵌入/未知附件"占位块，看不到谱面；同一份 `.jps` 用文件视图打开却是正常的。
- **根因**：扩展名注册（`registerExtensions(['jps'], …)`）只影响"主动打开文件"，**不影响嵌入**——Obsidian 渲染 `![[x.jps]]` 时先插入自己的**未知附件占位块**并异步等待嵌入处理器；即使处理器随后渲染成功，占位块也会**把它替换/顶掉**（处理器执行过早时尤其明显）。
- **修复**（`src/embed.ts` 重写为"先挂载、被覆盖再重挂"）：
  - 处理器**立刻**在嵌入位置挂载渲染面板（不等异步读文件完成，避免占位块先占位）；
  - 用 `MutationObserver` 监听嵌入容器：**发现自己的节点被占位块替换掉就重新挂载**（最多 5 次，防死循环）；
  - 另加 120ms / 600ms 两次延迟补挂（覆盖 Obsidian 异步渲染时序）；内容用"**先读后清**"（`cachedRead` 后再替换容器，避免清空时把刚写入的内容一起清掉）。
  - 文件不存在时仍在原位提示"找不到谱面文件"（不静默留白）。

## 修复：深色主题下工具栏/设置图标是白方块

- **现象**：深色主题里谱面上方一排按钮的图标显示为**纯白实心方块**（看不出形状），浅色主题下也偏"发灰的块"。
- **根因**：`styles.css` 里给"谱面纸张"设白底的选择器 `.ijipu-score svg` **过于宽泛**——工具栏/设置对话框的**图标 svg 也被命中**，于是图标拿到白底 + 谱面文字色，笔画被"糊"成方块。
- **修复**：
  - 纸张白底规则**收窄到真正的谱面 svg**（`.ijipu-svgs .ijipu-page-svg > svg`），图标不再被误命中；
  - 工具栏按钮**显式配色**（`color: var(--text-normal)` + `stroke: currentColor`，深色主题下用 `--text-muted` 兜底），不再依赖继承；同批修复里给图标加的配色兜底一并保留。
  - 已用**加载真实 `styles.css` 的渲染夹具**核对：图标笔画随主题色变化、无白底方块。

## 验证

- `npm run build`（`tsc -noEmit -skipLibCheck` + esbuild production）通过；`main.js` 已确认含新逻辑（`MutationObserver` 重挂 + 收窄后的纸张选择器）。
- `npm run smoke`：**99 项断言全绿**（本次改动不涉及纯逻辑断言，回归无退化）。
