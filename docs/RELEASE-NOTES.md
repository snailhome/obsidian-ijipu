## 为什么是 PATCH 而不是 MINOR

插件仓库本轮**自身代码零改动**（改动只有三类：同步过来的 `vendor/engine/**` 7 个文件、按顺序铁律
重新生成的 `src/gen/webappAssets.ts` 嵌入产物、版本号与说明文档）。按 SemVer 的"Bug 修复 + 内部依赖更新"
走 **PATCH**（先例：`0.35.1`、`0.41.1`、`0.41.2`、`0.41.3`、`0.41.4`）。

## 引擎：`0.38.2 → 0.38.3`（同步过来的一处排版修复 + 一条共用判据）

1. **`&ds`（D.S.）与小节序号方框不再重叠**（`adj970`，用户截图实报）：两者都挂在小节线**正下方**、
   而 y **各算各的**（序号方框由布局端给、线下方文本记号由渲染端现算）⇒ 实测完全重叠。
   现在把"线下方记号"的判据与几何**收敛进 `layout/spacing.ts`**（`hasBarDownMark` / `barDownMarkLabel` /
   `barDownMarkFontSize` / `barDownMarkBaselineY` / `barDownMarkInk` / `barDownMarkSpan`），
   序号方框**上下错开优先、下方塞不下才左右错开**；`x` 与 `yBarBottom` 的**口径不变**
   （`adj906` / `adj967` 两条断言照旧成立）。
   ⚠ 实测结论：默认版式下"线底 → 歌词墨迹上沿"只有 **14.6px**，而需要 **16.4px** ⇒ **有歌词时走左右错开**
   （撑行距会违反 `adj625c`："序号显隐不得影响排版"）。
2. **`localAssetRefs`**（`adj969`）：判"这份谱到底要不要一个基准目录"的**共用口径**
   （相对路径算；`data:` 内嵌与 `[[双链]]` 不算），应用与插件消费同一份。
3. **行首序号那一档统一挪到上一行行末小节线**（`adj967d`）与**末尾"空段串"不编号**：**上一版（0.38.2）已发**，
   此处只是随版本号一并记录口径。

`vendor/engine` 按**逐文件 SHA256 双向对比**同步：同步前差异 **7 处**（正是本轮改过的那 7 个文件：
`index.ts` / `overlayAsset.ts` / `types.ts` / `layout/index.ts` / `layout/spacing.ts` / `render/index.ts` /
`render/inkBox.ts`），同步后**差异 0、插件侧多余 0**（闸门 `adj770` 绿）。

## 更新：内嵌的 iJipu 应用 `0.65.0 → 0.66.0`

按项目的**顺序铁律**（`E-2026-374`）：先在应用仓库提交并打 tag（`v0.66.0`：`eb1303c`）、推送，
**再** `npm run build:embed` + `node scripts/embed-emit.mjs` 重生成嵌入产物。
跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）**通过**（产物里 `appVersion: "0.66.0"`）。

嵌入版这一版带来的东西：

1. **"文件方式"打开的谱也能读相对路径的图**（`adj969`）：插件这一侧**看不到"授权文件夹"那一步** ——
   嵌入版跑在跨源 iframe 里（弹不了文件夹选择器，我们也不弹），库内文件本来就由宿主（vault）提供基准。
   这条主要影响**用浏览器打开嵌入版 / PWA** 的场景。
2. **标题改为「文件名.jps - 爱记谱 iJipu」**（`adj971`）：嵌入版里那是 iframe 自己的 `document.title`
   （不显示在 Obsidian 的标签页上），实际影响的是"**打印 / 另存为 PDF 的默认文件名**"这条链；
   插件自己的标签页标题仍由 Obsidian 按当前笔记显示（未动）。
3. **`&ds` 与序号方框错开**（`adj970`）与**小节序号两条口径**（`adj967d` / `adj967e`）：库内 `.jps`
   的预览与嵌入版都跟着修。
