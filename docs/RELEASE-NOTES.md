# 爱记谱 iJipu 0.14.0

> 本版只做一件事：**同步 `@ijipu/engine`（0.15.0 → 0.16.0）**——带来「小节时值校验」这一**新告警**，
> 以及多声部演奏顺序/版面三处修复。插件自身代码无功能改动（只更新了一条 smoke 断言的口径）。
> 0.13.0 → **0.14.0**（MINOR：插件里从此多看到一类**新告警**，不只是修 bug）。

## 新增（来自引擎）

- **小节时值校验告警**（`adj594`）：每个小节"带时值元素"的时值之和应等于当前拍号
  （`P: 4/4` → 4 拍、`P: 6/8` → 6 拍），不符时在**谱面下方的告警区**给出一条
  （`warning`，**不阻断渲染**：谱面照常显示、照常试听），并附「正确写法」提示与行/列位置。
  - **临时拍号** `|"p:2/4"` 从这条小节线**之后**的小节起生效、一直延续到该音轨的下一个临时拍号
    （跨行也延续；`Q1:`/`Q2:` 各算各的）；
  - **小节号按音轨累加**：同一旋律折成多行 `Q:` 时，第二行的小节接着数（不会又从"第 1 小节"开始）；
  - **首小节（弱起）只查"整数拍"**（`adj595`）：`1 |`、`1 2 |` 都合法，2.5 拍这种"半拍"才报；
  - 记号/括号/渐强渐弱/乐器切换/临时段/倚音/空小节不计入；没写 `P:` 时按 4/4 兜底。
- 例：`P: 4/4` 下写 `Q: 1 2 3 4 | 1 2 3 |` ⇒ 告警「第 2 小节共 3 拍，与拍号 4/4（每小节 4 拍）不符」。

## 同步的引擎修复

- **单声部行与多声部组混排时的演奏顺序**（`adj595`）：`Q:`（单声部）与 `Q1:`+`Q2:`（多声部组）混写时，
  演奏顺序为「单声部 → 第一组（两声部**同时**）→ 第二组 → 单声部……」，与排版上下分块一致；
  此前穿插的单声部行会被挪到所有多声部块之后，且块内按"该声部下一个未占用的行"错配
  （块**前面**那行单声部会被吸进第一个多声部块）。
- **多声部组末尾的 `:|`**（`adj596`）：`:|` 写在**每个声部行末**时，反复回跳此前按"行"推进 ⇒
  后写的声部要**晚一整遍**才演奏（用户报"第二组多声部只演奏了第一声部"）；改为多声部组**按小节整体**展开，
  回跳发生在整小节排完之后；顺带修「跨声部连音合并 / 跨声部借时值」。
- **版面**：多声部块"一行放不下"（`adj593`，末音符越出右边距 45px）；末尾 `&ykh` 压在末小节线上（`adj596`）；
  块首 `&zkh` 让"大括号 → 声部"多出一段空白（`adj597`）。

## 验证

- `tsc -noEmit -skipLibCheck`：退出码 0
- `npm run smoke`：**160 passed, 0 failed**。引擎换新后只有**一条断言口径过时**：「跨行渐强/渐弱的告警带正确写法」
  原先要求**所有**告警的 hint 都含「同一行」，而新增的小节时值告警也进同一个 `warnings` 列表 ⇒
  已改为**只校验渐强那条**（`w.text.includes('不能跨行')`），不是放宽、而是对准。
- `vendor/engine` 与应用 `packages/ijipu-engine/src/engine` **逐文件 SHA256 一致**（35/35，含新增的 `measures.ts`）。

## 升级

打开任意 `.jps` 即可。小节拍数与拍号对不上时，谱面下方会出现告警（**不影响谱面显示与试听**）；
多声部混排的曲子试听顺序会与谱面分块一致。桌面端与手机端界面均无变化。

## 变更

- 无破坏性变更：本轮只同步引擎（含一类新告警 + 三处修复），插件代码只改了一条 smoke 断言。
