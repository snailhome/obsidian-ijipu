# 爱记谱 iJipu 0.6.0

> 本版随 `@ijipu/engine` 同步 **adj395 / adj396**，修的是两类「看起来能显示、其实时值算错」的问题：
> ① **等时值连音组 `(y …)`** 以前按各自写的减时线时值算，`3./ 6,// (y3/ 2/ 1/)` 里三个音被当成 1.5 拍
> ——越出小节、拍位漂到下一拍、**减时线被拍线切断**；现在组占「这一小节剩下的那一截时值」，
> 占宽同样按剩拍分摊，**减时线连成一条**（跨拍也不断开）并标数字。
> ② **倚音**以前**不占主音符时值**（时值写死 1/8 拍，前倚音借前一个音符的时间、后倚音借后一个音符的时间），
> 后倚音还一律画在数字右侧、压住增时线/附点；现在倚音**从主音符内部切时值**，并新增
> **增时线/附点之后写后倚音**（`3 -[h5/]`）——谱面上画在 `-` 之后，演奏时主音符先奏满、最后一小段才是倚音。
> 插件侧不需要改代码，只是引擎换新版；得益于上一版「告警不阻断渲染」，新增的语法告警也只会提示、不会影响显示。

## 改进：等时值连音组 `(y …)` 的时值、占宽与减时线（adj395）

- **规则**：组总时值 = **小节名义拍数 − 组外音符实际时值**（就是"这一小节里剩下的那一截"）。
  例：2/4 的 `3./ 6,// (y3/ 2/ 1/) |` —— `3./`（0.75 拍）+ `6,//`（0.25 拍）已占 1 拍，
  所以组占**剩下的 1 拍**，组内三音**各 1/3 拍**（演奏时值也是 1/3 拍）。
- **占宽同样按"剩余时值"分摊**：组内每个音符的占宽 = 组总占宽 ÷ 音符数（不再按各自写的 `/` 时值算成 1.5 拍）。
- **减时线连成一条**：一个三连音/多连音就是一个连音组，**跨拍也不断开**，也不与同一拍内的组外音符共线；
  弧线上方标出组内音符数。
- **修的两个根因**：① 空间优先布局专用的时值拆分不认连音组的覆盖时值（拍级路径本来是对的，所以只有默认布局错）；
  ② 减时线的分组键只有"拍"，跨拍连音组的第 3 个音会被拍线甩出去。现在给连音组打了**解析期生成的稳定组号**，
  渲染只消费，不再依赖几何位置推断。

## 新增：增时线/附点之后的后倚音（adj396）

- **写法**：`3 -[h5/]`（等价 `3-[h5/]`）、`3.[h5/]`（等价 `3 .[h5/]`，独立附点归前音符）。
- **演奏**：主音符总时值 2 拍（附点后为 1.5 拍）——主音符**先奏满增时线/附点**（奏到末尾前），
  **最后 1/4 拍**才奏后倚音；总时值不变。
- **谱面**：倚音画在**增时线/附点之后**（紧靠这些元素），弧线随之落在其后。
  无增时线也无附点的后倚音仍紧贴数字右上角（既有观感不变）。

## 修复：倚音不再向相邻音符"借时间"（adj396）

- **现象**：`3[2/]` 听到的是「1/8 拍硬的倚音 + 整 1 拍主音符」，不是「1/4 拍倚音 + 3/4 拍主音符，合计 1 拍」；
  前倚音会挤占前一个音符的尾巴、后倚音会挤占后一个音符的开头，整曲被撑长。
- **规则**：单个倚音实际时值 = **`1/2^(括号内减时线条数 + 1)` 拍**（写 `2[3/]` → **1/4 拍**＝实音符的 `2//`，
  "再减一半"；与"倚音减时线条数 = 书写条数 + 1"的显示规则自洽）。主音符发声时值 = 总时值 − Σ倚音时值。

  | 写法 | 演奏 | 谱面 |
  |---|---|---|
  | `3[2/]` 前倚音 | 先 1/4 拍倚音 2，再 3/4 拍主音符 3，合计 1 拍 | 倚音在数字左上角 |
  | `3[h2/]` 后倚音 | 先 3/4 拍主音符 3，最后 1/4 拍奏倚音 | 紧贴数字右上角 |
  | `3[3/2/]` 多倚音 | 1/4 + 1/4 倚音，主音符余 1/2 拍 | 依次左排 |
  | `3 -[h5/]` / `3.[h5/]` | 主音符先奏满（1.75 / 1.25 拍），末段 1/4 拍奏倚音 | 画在增时线/附点之后 |

- **新增告警**：倚音总时值超过主音符时值（此时主音符会被钳制为 0 拍、不发声），并给出正确写法。
- **连带修复**：连音线内的同音连奏合并此前会把长音**并到倚音事件**上（后倚音事件排在主音符之后），
  现改为按主音符事件合并，并规定带倚音的音符不参与合并。

## 验证

- 引擎 `npm run smoke` 新增 **35 条断言**（连音组 14 + 倚音 21），全绿；失败项 17 == 改动前基线。
- 两处新规则都按**空间优先（默认）与时值优先两种布局**各断言一遍（此前只测非默认的时值优先，等于没测）。
- 无头 Chrome 截图核对：`3./ 6,// (y3/ 2/ 1/) |`（三音一条减时线 + 上方数字 3）、跨拍组、`(y1 2 3) 4 |`、
  `3[2/]`、`3[h2/]`、`3[3/2/]`、`3 -[h5/]`（两种布局）、`3.[h5/]`（两种布局）、`3[h5/]` 基线均正确。
- 插件侧 `tsc -noEmit -skipLibCheck` 通过；`main.js` 为构建产物、不入库。
