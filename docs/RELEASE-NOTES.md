# 爱记谱 iJipu 0.32.0

> ⚠ **本版有一处破坏性变更**：**删除「笔记 frontmatter」设置层**。
> 以前可以把 `ijipu_*` 键写在笔记顶部的 `---` 之间（Properties 面板 / YAML）来覆盖代码块的排版；
> **从本版起这些键不再生效**（插件里已没有任何读取 frontmatter 的路径）。
> 迁移很简单：把那几项写进代码块里的 `# jps-config:{…}`（或用预览工具条的「设置」按钮改，插件会自动写回）。
> 0.31.1 → **0.32.0**（MINOR：删除一层设置能力，属破坏性变更）。
> `.jps` 文件与既有谱面**语法零改动**；没写过 `ijipu_*` 的用户**完全不受影响**。

## 为什么删（用户判断）

- **对 `.jps` 文件用不上**：`.jps` 文件视图与内联嵌入**从来没有**这一层（只读文件内的 `# jps-config`）；
- **对"一个笔记里多个 ` ```jps ` 块"太粗**：frontmatter 是**笔记级**的，多个块会被同一套值一起覆盖；
- **不随谱走**：别人拿到同一份谱看不到同样排版；
- 而**源内的 `# jps-config:{…}`** 既跟着谱走、又能**逐块**写 —— 本来是唯一该用的口径。

## 删了什么

- 整个 `src/frontmatter.ts`（键名兼容、值类型转换、未识别键的"最近键名建议"、已降级键提示、字段表）。
- 优先级简化成两层：**引擎默认 < 插件设置 < 谱面源码内的 `# jps-config`**。
- 预览工具条的「frontmatter 覆盖 N 项」徽标、「未识别的 frontmatter 键」「已不再随谱保存的设置」两条提示、
  设置对话框里的「未随谱携带 N 项」区块（该来源恒为空）——一并删除。
- 设置页那两块「复制 frontmatter 模板 / 复制最小模板」按钮（以及只给它们用的剪贴板回退实现）。
- 设置面板每项下方的键名说明从「frontmatter 键」改为「设置项」（键名本身就是写进 `# jps-config` 的键）。
- README 的 frontmatter 章节与 YAML 示例删除；对照表改名「**设置键对照表（写进 `# jps-config` 用）**」，
  键名去掉 `ijipu_` 前缀（= 引擎 `PageConfig` 字段名），并新增一段谱内设置示例。

## 同一版里的其他修复与改进

- **编辑模式（实时预览）里工具条与 `</>` 不显示** —— 修好了：根因是 `ijipu-cm-host` 那个类只在挂载时
  打一次，而实时预览里 CM6 会复用/重建块容器 ⇒ 类丢失 ⇒ 悬停时宿主的 `.cm-embed-block:hover{overflow:hidden}`
  把浮在块外的工具条整条裁掉（`</>` 同时退回主题色，白纸上等于看不见）。现在每次显示工具条前都会重新确认这个类。
  另外 `</>` 的让位口径收紧：**只有确实找到宿主的 `.edit-block-button`** 才撤掉插件自己那枚。
- **设置页顶部改成应用的品牌头**（用户要求）：应用同款图标 +「爱记谱（iJipu）」+ 标语「码即成，谱自现」，
  版本串也逐字对齐应用的格式：`v0.32.0 (日期 @提交)`；并**并排显示嵌入版应用的版本**
  （`嵌入版 iJipu：v0.50.0`）—— 一眼分清"插件版本"和"嵌入版版本"。
- **「支持作者」文案收成一句**：「如果这个插件帮到了你，欢迎扫码下方的微信赞赏码支持一下。」
  并去掉「在浏览器打开」按钮（码就在正下方，外链是多余入口）。
- **「谱面裁剪」那条诊断改成人话**：标签改为「谱面裁剪（诊断信息，无需操作）」并说清用途；
  记录内容改成 `HH:MM:SS · 人话`（如 `14:32:07 · 按墨迹裁剪 488×107（整页 595×842，高度只剩 13%）`），
  不再出现"三次重试都没量到（元素始终不在渲染树里？）"这种像报错的黑话。
