## 为什么是 PATCH 而不是 MINOR

插件仓库本轮**自身代码零改动**（改动只有：按顺序铁律重新生成的 `src/gen/webappAssets.ts` 嵌入产物、
版本号与说明文档）。`vendor/engine` 逐文件哈希比对**差异 0**（应用这一版没碰引擎）。
按 SemVer 的"内部依赖更新"走 **PATCH**（先例：`0.41.1`～`0.41.6`）。

## 引擎：`0.38.4`（**未改动**）

## 更新：内嵌的 iJipu 应用 `0.67.0 → 0.67.1`

按项目的**顺序铁律**（`E-2026-374`）：先在应用仓库提交并打 tag（`v0.67.1`：`3bcedf0`）、推送，
**再** `npm run build:embed` + `node scripts/embed-emit.mjs` 重生成嵌入产物。
跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）**通过**（产物里 `appVersion: "0.67.1"`）。

嵌入版这一版带来的东西：

1. **标题只显示文件名**（`adj978`）：在 Obsidian 里基本看不到差别（页签名一直是文件名，
   由 `jpsViewTitle()` 决定）；好处是"**打印 / 另存为 PDF 的默认文件名**"这条链更干净 ——
   以前标题里带着应用名，会顺着 `document.title` 漏进打印名。
2. **状态栏版本号**（`adj975`）：嵌入版底栏右侧现在显示 `v0.67.1 (日期 @commit)`（窄屏收起日期/指纹），

3. 云端/桌面端的行为没有变化；插件自己的设置项与 `.jps` 语法**一条没动**。
