## 修复：「保存到谱面」写不进文件（**假成功**）+ 取消总开关被设置层压回来（用户实报，`adj965l`）

- **现象**（用户原话）：「插件，代码块预览设置里，我取消了水印启用，保存笔记，重新打开笔记，
  发现水印还启用着，说明取消水印启用没有保存到谱面」。用户随后确认了四个细节：
  界面 = 代码块工具条的「设置」对话框 →「水印」页签；按钮 = **「保存到谱面」**；
  屏幕上是**成功提示**；当时笔记处于**阅读模式**。
- **根因①（假成功）**：代码块的写回原来只判"有没有一个指向这份笔记的 MarkdownView"，
  于是**阅读模式**也走编辑器那条路 —— 而阅读模式里那个 editor **不是这份文件的活动缓冲区**：
  `replaceRange` 既不报错、也写不进文件，只换掉了插件**自己缓存**的那份源码（**预览当场看着好了**）
  ⇒ 提示"已写入谱面"，**文件一个字没动** ⇒ 重开就回来了 ✗。
  插件在「打开源码」那处早就因为同一原因先切成 source 模式再动编辑器 ⇒ **判据存在，只是写回这条路没跟上**。
- **根因②（设置层又赢）**：`保存到谱面` 是"整份草稿 + **默认差量模式**"，而差量模式认的"默认"
  **只有引擎默认一层** ⇒ 取消总开关（值 = 引擎默认）被当成默认**删掉**；只要插件设置层（本库默认）
  供着 `true`，删掉就等于"这一项从此跟随设置层" ⇒ 取消不生效（`E-2026-443` 洞②的残留）。
- **解决**（都落成**纯函数**，判据才机器化得起来）：
  · `src/sourceEdit.ts` 新增 `writeRoute(mode, viewPath, sourcePath)`：只有"同一文件 **且** 视图确实处于
    可编辑模式"才用编辑器（保留撤销栈）；阅读模式 / 视图是别的笔记 / 没有视图一律走
    **整文件事务写**（`vault.process`，以落盘为准）；编辑器那支另包 try/catch 兜底。
  · `src/config.ts` 新增 `scoreWritePayload(draft, baseline)`：**要写**＝值 ≠ 引擎默认（设置层带来的
    非默认项必须随谱走，换台机器才一样）**或** 值是引擎默认但本库默认层供的不是它（**显式钉住**）；
    **不写**＝两层都等于它（谱面保持最小，尊重"默认值就别写进谱面"的定稿口径）。
    写入改用 `mode:'full'` —— **必须** full，差量模式会把刚决定"要钉住"的默认值再删一次 ✗。
  · `src/scorePane.ts`：对话框写入改用上面两个纯函数；**三处**"可选调用 + 紧跟成功提示"的写法
    （对话框 / 虚线拖动 / 格式化）一律改成"取出来再判一次，没有入口**如实报错**"，格式化那处还补了失败提示。
