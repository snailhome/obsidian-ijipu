# 爱记谱 iJipu 0.4.2

> 本版随 `@ijipu/engine` 同步 **adj391**：小节线线宽按用户规则改为**细 1 / 粗 2**，高八度点改为与音符
> **水平居中**；并根治一处长期隐患——小节线的「线组几何」此前在渲染与布局各写一份，
> 缩小线宽时占位表没跟着改，导致线组整体偏左、预留宽度虚胖、线与线间距悄悄从 1px 变成 1.2px。
> 现在线组几何只有一处定义，渲染与占位共用，改线宽只改一个常量。

## 引擎同步 adj391：小节线线宽（细 1 / 粗 2）+ 高八度点与音符水平居中

- **小节线细线 0.9 → 1、粗线 1.4 → 2**：线宽常量集中在引擎 `layout/spacing.ts` 的 `BARLINE_W_THIN`/`BARLINE_W_THICK`（仍**不随字号缩放**，只有线高与反复点半径随字号）。
- **线组改为以小节线中心对称**，线与线间距恢复 `adj55` 原意 **1px**（`adj104` 因"线左缘固定、右缘内收"实际变成了 1.2px），线与反复点仍 1.2px。
- 各类型线组总宽随之校正（占位与绘制一致）：`|` 1、`||` 4、`||/` 3、`||:` 6.6、`|:`/`:|` 7.6、`:|:` 13.2、`|*` 1（占位不绘制）、`|/` 0（不占位不绘制）；小节线最小占位 9.1 → 9（= 单线宽 1 + 两侧各 4px）。
- **高八度点与音符水平居中**：此前高八度点比数字槽中心额外左移 1px，现高/低八度点统一取**数字槽中心**——与增时线、音符上方修饰符、音符注释同一中心。
- 引擎侧改动：`layout/spacing.ts`（新增 `barlineGeometry()` 作为线组几何**单一来源** + 新线宽 + `barlineTotalW` 由几何派生）、`render/index.ts`（`renderBarline` 改为遍历几何绘制，不再写死偏移；临时节拍分数与 `&fine/&dc/&ds` 标记的横向基准改由几何给出）、`layout/index.ts`（删除自带的 `barlineTotalW` 总宽表，改从 `spacing.ts` 导入）。`vendor/engine` 与主项目**逐字节一致**。

## 修复：小节线「渲染偏移」与「布局占位」两处各写、缩线宽时未同步

- **现象**：复合小节线（尤其 `:|:`）看起来**整体偏左**、两侧留白不均，且小节线周围比"看上去需要的"更空；`||` 两条线之间的缝比文档里写的 1px 宽一点。
- **根因**：同一件事（线组几何）在**两个文件各维护一份**——渲染里写死一整套偏移，布局里另有一份总宽表；`adj104` 缩小线宽时只改了渲染，且改法是"线左缘固定、右缘内收"，于是：① 占位表仍是旧线宽（预留比实际宽 0.2~3.0px）；② 线组不再以小节线中心对称（与布局"x = 线组中心、半宽 = 总宽/2"的假设相反）；③ 线与线间距从 1px 变成 1.2px。
- **修复**：线组几何收敛为引擎 `layout/spacing.ts` 的 `barlineGeometry(type)`（元素序列 + 间距 → 总宽 + 各元素相对中心的偏移），渲染遍历该几何绘制、布局的 `barlineTotalW` 直接取几何总宽——**改线宽只需改一处**。插件侧无需额外改动（渲染由引擎负责）。

## 验证

- 插件 `npm run smoke`：**99 项断言全绿**；`npm run build`（`tsc -noEmit -skipLibCheck` + esbuild production）通过。
- 引擎侧（主项目）：`npm run smoke` 失败项与改动前基线**完全一致**（17 项既存，无新增），新增断言覆盖线宽常量、线间距、六种类型的"渲染几何逐项 == `barlineGeometry`"、占位总宽表与几何对称性；无头 Chrome 截图核对线宽与高八度点位置（示例 `yufa-quangai`：点 `cx=51.93` 与数字槽中心 `47.9 + 13×0.31 = 51.93` 一致）。
- **副作用**：复合小节线（`|:`/`:|`/`:|:`）占位变准后，其后的音符水平位移 0.4~0.8px；贴右边距行的终止线右缘因布局取整（0.1px 精度）理论上有 ≤0.05px 外溢。
