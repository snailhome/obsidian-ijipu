## 修复：替谱段 `{tp … }` 的歌词对位（`adj675` / `adj675b` / `adj675c`，用户三次实报）

- **量出来的数**（真谱 `2.曲谱集/可能/可能.jps`，打印布局结果得到，不靠肉眼）：
  · 用户标红的那个音 = **槽位 17 / 拍位 10**（确实已回到主旋律）；
  · 替谱 `{tp (3/ 2//) (2// 2/) 1/}` = 拍位 `[8,10)`、**自身 5 个音**、**只覆盖 4 个主旋律槽位**；
  · 旧实现按"5 个音占 5 个槽"排 ⇒ `曾` 被抢到替谱第 5 音上、红 `2` **一个字都没有**、`经` 顺延到下一个音。
- **改法**（引擎 `layout/index.ts`，插件侧逐字节同步）：
  · 新增纯函数 `spliceTpNotes`：把替谱的音**接进"这一遍的发声音序列"**（替谱段用它自己的音
    **替换掉它覆盖的那几个**主旋律音），字按槽位对到**第 k 个发声音**——与歌词的全局口径
    （"第 k 个字 = 第 k 个音"）同源；
  · "覆盖几个主旋律音"用引擎已有的 `mainSpansInRange`（拍跨度 → 槽位区间）算，不另立几何；
  · ⚠ **替谱音少于覆盖数**时，多出来的那几个主旋律音**仍然是字位**（`adj658` 的原口径"多出来的字保持原位"）
    ——少了这一条，整行可用字位凭空少几个、末尾的字没地方放；
  · 该处理从"段循环里逐段挪字"挪到**整组一次算**（同一行多处 `{tp}` 的偏移会累加）；
  · 补出来的字，`y` 按「**本组 + 本歌词行 + 目标音下方最近**」取；挪字时**同时写 `id` 与 `slotW`**。
- **实测结果**：真谱第二行 `看@291 清@317 曾@349 经，@368 可@387 … 有@509 双@525`，
  与"发声音序列"逐个对齐；联动指向逐字核对 **0 个不一致**（每个字都指向它被画在下面的那个音）。
