# 爱记谱 iJipu 0.36.3

> **本版是引擎同步版**（PATCH）：同步应用引擎的**两组「上下对齐」修复**
> —— 段层逐拍对齐主旋律的「格」、增时线改为「格内左对齐」；
> 并把**内嵌的 iJipu 应用**从 0.55.1 更新到 **0.55.2**。0.36.2 → **0.36.3**。
> **既有谱面、`.jps` 语法、代码块参数全部零改动** —— 变的只是渲染出来的几何。

## 引擎同步：段层逐拍对齐主旋律的「格」（应用 `adj905v`，用户裁定 ①）

`{bz … }` / `{dsb … }` / `{tp … }` 段层与主旋律的**逐拍对齐**此前会**越往后越偏**
（最小例 `{bz 1, 3, 5, 3,} 3 - - - ||` 实测：段层每拍步进 `25`，主旋律是 `29`）。
现在段层拍位直接落在**主旋律的格**上 —— 第 0 拍仍等于"数字位"（数字与段层首音逐个对齐，不变），
其余各拍的**步进等于主旋律的格**：

- 段层拍列由 `62.5 / 87.5 / 112.4 / 137.4` 变为 `62.5 / 91.5 / 120.4 / 149.4`（步进 `29` == 主旋律）；
- 应用默认的**空间优先**布局下，段层与主旋律**逐拍重合**（时值优先路径保留与数字一致的常量偏移）。

## 引擎同步：增时线改为「格内左对齐」（应用 `adj905w`，用户看图定标）

`-`（增时线）原来画在**所属拍段居中**，而数字落在"格左缘 + 偏移"上 ⇒ 段层与主旋律看着错开。
现在增时线的**墨迹左缘 = 该拍格左缘 + 数字的格内偏移**（与数字**同源**）：

- 空间优先（默认）下增时线与段层数字**逐拍对齐**（落在同一列）；
- 时值优先路径位移约 `2px`（数字本就在拍槽内近似居中，属正常）。

> 两条都属于"**上下对齐**"这条线：口径与验收方式见应用仓库的
> `docs/ALIGNMENT-PRINCIPLES.md` §五之四（含本轮 `adj905w` 补记）。

## 更新：内嵌的 iJipu 应用 0.55.1 → **0.55.2**

嵌入版产物按项目的**顺序铁律**生成：先在应用仓库定稿版本号（0.55.2 提交 + tag `v0.55.2`），
再 `npm run build:embed` + `node scripts/embed-emit.mjs`。
跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）因此**由红转绿**。
