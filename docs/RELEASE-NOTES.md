## 为什么是 PATCH 而不是 MINOR

插件仓库本轮**自身代码零改动**（唯一改动是重新生成的 `src/gen/webappAssets.ts` 嵌入产物与版本号），
引擎**零改动**（`vendor/engine` 逐文件 SHA256 对比：差异 0、插件侧多余 0 —— 不需要同步）。
按 SemVer 的"内部依赖更新 / 无接口与行为变化"走 **PATCH**（先例：`0.35.1`、`0.41.1`、`0.41.2` 都是 PATCH）。

## 更新：内嵌的 iJipu 应用 `0.63.2 → 0.64.0`

按项目的**顺序铁律**（`E-2026-374`）生成：先在应用仓库**提交并打 tag**（`v0.64.0`：`953b640`）、推送、
出 GitHub Release，**再** `npm run build:embed` + `node scripts/embed-emit.mjs` 重生成嵌入产物。
跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）**通过**（产物里 `appVersion: "0.64.0"`，
来源标记 ` * 来源：ijipu v0.64.0`）。

嵌入版这一版带来的三件事（用户口径，详见应用侧 `docs/FILE-MODEL.md`）：

1. **两边都改了不再只能"整体二选一"**（`adj966f`）：差异框每个改动块给「用左 / 用右」、顶部
   「全用左 / 全用右」、底部「应用（并保存）」；**以本地为底**，只有一边改过的块**自动合好**
   （此时确认条直接说"已自动合好（N 块互不重叠）"并给一个「应用」按钮）；两边改**同一块**才算冲突，必须你来选。
2. **第六态「两边都改过」**（`bound-conflict`）+ 应用护栏：应用前本地/外部各留一份备份、
   应用 = **一步历史**（可撤销）、立刻跑解析器体检（问题进问题面板）、写回后基准刷新回到"已保存"。
3. **分层口径**（`adj966g`，用户 2026-10-17 拍板）：**要权限确认的那一档继续用「工作区」底栏**
   （手机端 Web / PWA：底栏默认就展开在「工作区」）；**PC 各档继续用系统文件**（点「打开…」一律弹系统
   文件选择器）；**插件继续用 Obsidian 端的文件管理方式**（文库即工作区，宿主自己管文件）。

## 引擎：保持 `0.38.1`（无需同步）

应用侧 `packages/ijipu-engine/src/engine/**` 本轮**零改动** ⇒ `vendor/engine` **不需要同步**。

差异 **0**、插件侧多余 **0**（闸门 `adj770` 绿）。
