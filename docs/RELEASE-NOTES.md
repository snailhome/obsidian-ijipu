## 为什么是 PATCH 而不是 MINOR

按 `docs/VERSIONING.md`「两库版本号各自独立、各按自身代码更新量递增」＋插件历史口径：
**只有"嵌入版产物重生成"这一类改动**（插件自身 `src/` 未动、也没同步引擎）走 **PATCH**
（先例：`0.31.1`、`0.35.1`、`0.35.2`、`0.36.3`、`0.39.1`、`0.39.2`）。
本轮插件仓库 `git diff 0.39.2..HEAD` **只有 `src/gen/webappAssets.ts`（生成物）与 `main.js`（产物）**，
没有任何手写源码变化 ⇒ 判 PATCH。

## 更新：内嵌的 iJipu 应用 0.60.0 → **0.61.0**

按项目的**顺序铁律**（`E-2026-374`）生成：先在应用仓库**定稿并提交**版本号（**0.61.0**，已打 tag
`v0.61.0` 并推送、安装包与 GitHub Release 都已产出），**再** `npm run build:embed` +
`node scripts/embed-emit.mjs` 重生成嵌入产物。跨仓闸门 `adj733`（嵌入产物版本 == 应用 `APP_VERSION`）
**通过**（产物里 `appVersion: "0.61.0"`）。

## 引擎：本轮不需要同步

应用本轮 `packages/ijipu-engine/src/engine/**` **一个文件都没动**（引擎包仍是 **0.36.0**）
⇒ `vendor/engine` 与上一版**逐字节相同**（逐文件 SHA256 对比：49 个文件、差异 0、插件侧多余 0），
**无需同步**（闸门 `adj770` 仍然绿）。
