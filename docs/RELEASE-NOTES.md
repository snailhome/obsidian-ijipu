## 为什么是 MINOR 而不是 PATCH

按 `docs/VERSIONING.md`「两库版本号各自独立、各按自身代码更新量递增」：本轮插件仓库自己**动了源码**
（`src/api.ts` 的 `renderSvg` 多一个 `assets` 参数、`src/main.ts` 的五个导出出口接线、
`src/overlayAssets.ts` 删除废弃函数）⇒ 是**行为修复 + 接口扩展**，判 **MINOR**
（PATCH 只留给"插件自身源码零改动、仅重生成嵌入产物"那种版本，先例：`0.31.1`/`0.35.1`/`0.39.x`）。

## 修复：导出 PNG / SVG 时水印与背景图丢失（用户实报，`adj965j` / `adj965k`）

- **现象**（用户原话）：「插件，jps 代码块如果背景使用 `[[]]` 双链时，预览显示是正常，
  但导出这 PNG 时没有背景」；用户随后补了关键对照：**嵌入版 iJipu 自己的导出是正常的**。
  第一轮修完后用户复测：**PNG 已经带背景了，SVG 还不能**。
- **根因**：两条导出入口的**取图能力不同**。插件工具条的导出命令走应用 RPC，只递**一段源码字符串**，
  而栅格化在嵌入版应用（iframe）里做 —— 那里**读不到 vault** ⇒ 背景图解析不出来。
  预览是**插件自己**渲染的（`vendor/engine` + `src/overlayAssets.ts` 能读 vault）⇒ 一直正常；
  嵌入版自己的导出走宿主桥 `readAsset`（EP-09 已接）⇒ 也没问题 —— 用户那条对照正好印证了定位。
- **解决（两版试错后定稿）**：唯一有效机制是「**宿主解析好 ⇒ 当参数递给渲染端**」，因为引擎渲染图片
  **只认 `assets` 里那份 `{href,w,h}`**（它零 DOM：量不到宽高、也读不到字节）。
  而「相对本谱的路径」与「`[[]]` 双链」两类取值**只有宿主**（插件，能读 vault、会解双链）解析得出来：
  - **位图两个出口**（复制图片 / 保存为 PNG）：资源放进 RPC 请求的 `params.assets` ⇒ 嵌入版应用
    校验后转给 `renderScoreToSvg` 的 `RenderOpts.assets`；
  - **矢量三个出口**（复制 SVG 文本 / 保存为 SVG / 命令「导出当前谱面为 SVG 文件」）：走插件自己的引擎，
    资源作为 **`api.renderSvg` 的第三个参数**转给 `renderScore(source, cfg, assets)`。
- **⚠ 第一版做法已删除**：把图**内联成 `data:` URI 写进那份临时源码**的 `# jps-config`
  —— **用户实测证伪** ✗（引擎不从源码里解析图片，源码里写什么都不够）。
  函数 `inlineAssetsInSource` 与调用点整体删除；桥的 `params.source` 上限由放宽到的 **8000000
  同时收回 500000**（放宽是为内联服务的，内联废了、理由没了；图片字节照旧走 `params.assets`）。

## 修复：`Alt` 手势与图片缓存要扛得住宿主重建面板（用户实报，`adj965e` / `adj965g`）

- **现象**：用户原话「切换水印后，`Alt+点按拖动` 时，又切回背景了」；
  「在 `Alt+滚轮` 调整背景大小时，右上角的信息显示一次，背景就消失一次，再切换水印/背景后又显示回来」。
- **根因**（同一条链）：一次手势落盘会 `writeSource()` 改写笔记里的代码块正文 ⇒ Obsidian 重新渲染
  那个代码块 ⇒ 面板被**销毁重建**。而「调整对象」原来存在挂载闭包里（重建即掉回默认的「背景」）；
  `destroy()` 又清了图片缓存（新面板第一帧无图 ⇒ 看着像"消失"，异步读盘回来才又出现，
  而切换水印/背景会触发重画 ⇒ 所以"切一下又回来"）。同族的还有：`destroy()` 没摘掉容器上的
  `wheel`/`pointerdown`（容器跨重建是同一个元素 ⇒ 一次 `Alt+滚轮` 被处理多遍）、
  没清那个 400ms 的落盘定时器（销毁后的面板会把上一代的值写回）。
- **解决**：凡是**必须活过宿主重建**的状态一律搬出挂载闭包（模块作用域），`destroy()` 负责摘监听、
  清定时器、置"已销毁"标记；图片缓存的失效改挂在**真正的原因**上（`vault` 的 `modify` / `delete`
  且按引擎的扩展名白名单判定是图片）——笔记 / `.jps` 的改动不再误清缓存。

## 新增：页面设置逐项写回审计（`adj965h`）

用户问「纸张 / 边距好像都没保存到谱面」。把 `defs.ts` 里**每个没有子键的字段**都取一个
"既非当前值、也非引擎默认值"的探针值，走一遍代码块真实的写回链路
（`resolvePageConfig → mergeConfigEdits → writeJpsConfig`），断言它真的落进 `# jps-config`；
另有一条"覆盖面自检"（防止"只测了两项就报绿"）。结论：**纯写回链路全部通过**（纸张与四个边距都在内）。

## 变更：「保存到谱面」只写对话框里的非默认值（用户定稿口径，`adj965i`）

用户原话：「先遍历谱面值，对比设置对话框里的值，如果设置对话框里是默认值，则谱面里这项删除。
然后再保存设置对话框里的非默认值。」⇒ 判据从"用户这次有没有动过它"改成"**对话框里的值是不是默认值**"。
旧口径有两个洞（都表现为"改完没保存 / 恢复原样"）：① 插件设置层供来的非默认值与生效值相同 ⇒ 一个字都不写；
② 改回引擎默认值时差量写入又把"等于默认"的键丢掉 ⇒ 设置层又压回来。
语义与它重合的「随谱固化（分享用）」按钮一并撤掉（`README` 与对话框「说明」页签已同步）。
