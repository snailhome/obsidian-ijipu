## 1.【未修】切到「整页」视图时，**预览区域持续来回抖动**（`adj911e`，用户 2026-10-13 实测）

- **现象**（用户原话）：「有时候切换到整页视图，预览页面会抖」；追问后确认：「**抖动是持续来回的**，
  **只是预览的那个区域**，jps 文件预览时，**嵌入块不会**」。
- **已知线索**：
  - 只有 **`.jps` 文件页**会出现；**嵌入块 / 代码块不出现** ⇒ 与"文件页那条路径"特有的东西有关
    （文件页比嵌入块多：文件栏 + `fileView.ts` 的**高度适配**容器 `contentEl` 的
    `unfixHeight`/`height` 那套，以及"整页进视界"的拟合）；
  - 只有**整页**（`page`）模式出现；谱面 / 满宽不出现（只有整页走 `publishPageFit` 的"进视界拟合"）；
  - **持续来回** ⇒ 是**振荡**，不是"抖一两下就收敛"。
- **机制判断（待验证）**：**拟合 ⇄ 尺寸**的反馈回路 ——
  `publishPageFit()` 按容器可用宽高算缩放并写入 ⇒ 尺寸变化触发 `pageFitObserver`（`ResizeObserver`，
  `adj871`）⇒ 再拟合 ⇒ 尺寸又变 ⇒ ……（典型来源：滚动条出现/消失、或 wrap 高度参与了下一次测量）。
- **修法候选**（按代价从小到大）：
  1. **幂等**：新算出的比例与当前已应用的相同（四舍五入后相等）⇒ **直接 return**，不再写尺寸；
  2. **换输入**：用**不受自身结果影响**的盒子（外层分栏/面板的可用宽高）作为拟合输入，
     而不是量"被自己撑大的那个 wrap"；
  3. **回调重入守卫**：`ResizeObserver` 回调里判定"这次变化是否我们自己刚写入造成的"，
     是则跳过；或把回调合并到一次 `requestAnimationFrame`。
- **下一步**：先按上面第 1 条试（最小改动），并加一条"同一尺寸下连续两次拟合结果必须相同（幂等）"的
  断言；若仍抖，再按第 2 条换输入。
- **为什么先记待办不马上修**：用户已要求**先记录、随后走发布链**；且根因未验证（本会话在"猜机制"上

## 2.【已修·adj915】量墨迹时那个"看不见却有 bbox"的元素 —— **元凶已点名**

> **2026-10-13 结案（`adj915`）**：用户确认「**多个 jps 文件会有这种情况**、且要求**修 DOM 的方式**」
> ⇒ 不再绕开，直接查根因并修显示端量取。

- **元凶（无头 Chrome 实测 55 张真谱 SVG，点名到元素）**：
  **引擎的矢量字形组** `<g transform="translate(tx ty) scale(K)">`（`glyphMarkup()` 产物：
  波音 / 滑音 / 延长记号，`K = fs/1024`，实测 `0.006831` / `0.009625`）与
  **带 transform 的记号文字** `<text transform="translate(cx symY) scale(0.75 1)">`。
  - 前者 `getBBox()` **恒为 `(36.2, 327.15) 951.6×349.91`**（字形源坐标，与它画在页面哪儿**无关**）
    ⇒ 并集右缘顶到 `987.8`（页宽只有 `595.28`，**超页右缘 392.52**）⇒ **右侧一大块空白**；
  - 后者 `getBBox()` 从 `x = -4.63` 起 ⇒ 并集 x 变负 ⇒ viewBox 往左扩 ⇒ **左侧空白**。
  - 根因一句话：**`getBBox()` 返回的是元素自身坐标系里的盒，不含元素自己的 `transform`**。
    此前那条"整块落在页面外"的过滤当然抓不到它 —— 它的 bbox 与页面**有交集**（正因坐标系不对）。
- **实测面**：55 张里 **30 张**的原盒并集超出页面（7 张往左、23 张往右）；
  **按 `svg.getCTM()⁻¹ · el.getCTM()` 归位后：0 张**超页。
- **修法（只动显示端量取）**：`src/cropBox.ts`（新增，纯函数 + 无依赖）+
  `scorePane.ts` 的 `measureContentBox`：① 每个盒先 `boxInRoot()` 归位；
  ② 再与整页矩形 `clipBoxToPage()` 求交（完全页外丢掉、跨界只算页内一截）；③ 并集夹一次；
  ④ 被丢掉/被截断的元素写进 `svgEl.dataset.cropNotes`，由 `applyViewBox` 拼进设置页那行诊断
  （样例：`已忽略页面外元素 g+tf@x36.2~987.8`）。
- **端到端实测（真 `mountScorePane` 挂进无头 Chrome，喂真实 `.jps`）**：
  `花又期二重奏` 墨迹 `494.98×749.75` ⇒ viewBox `498.98×753.75`（页宽 595.28）；
  `檐下声` / `追光者` 墨迹 `499.75×760.06` ⇒ viewBox `503.75×764.06` —— 都不再超页、不再有那一大块空白 ✓。
- **遗留（要用户看）**：用户当时的描述是"**左边**大空白"，而我实测这三份谱都是"**往右**扩"
  （会形成**右侧**空白）；vault 里确有 7 张是"往左扩"，但幅度只有 4.6~5.1px，**形不成"一大块"**。
  ⇒ 若用户重看后**左边仍空**，请给一张截图（或那份谱），用同一套探针再量一次即可定位。
- **关于 `adj911c`**：那条"墨迹以引擎 `inkBoxOfLayout` 为准"已被 `adj911e`（用户裁定）**回退**，
  现在墨迹仍由 DOM 量取 —— 所以本轮修的是**真路径**，不是兜底路径。
